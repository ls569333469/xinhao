# 1010｜吸筹背离本轮与历史分开展示方案

状态：展示更新已发布，页面验收通过（策略有效性、补采机制与全市场扫描验收不在本次范围）。用户授权：按本轮为主、历史为辅更新方案和正式前端。

## 一、问题与目标

旧主表以最近一条归档事件为主状态，可能显示十几天前的绿色确认，又在同格显示“本轮未触发”。ALT虽然本轮出现17.43倍放量，却因用户选择“最近记录已确认”而不可见。此次将本轮和历史查询明确区分，不修改A/B规则、C接入状态、采集、K线、事件库或补采任务。

## 二、主表字段

列名：吸筹背离 · 1小时。

| 本轮情况 | 主状态 | 辅助信息 |
| --- | --- | --- |
| 最新检查小时未触发，且前一小时无新的确认结果 | 无新信号 | 有过完整确认时显示“上次确认信号：日期 时间” |
| 最新小时已触发、当时持仓条件通过 | 放量价稳，等待确认 | 触发小时区间、等待哪次收盘 |
| 前一小时触发，本小时闭合后技术确认和结构资格均通过 | 吸筹背离已确认 | 触发区间、确认收盘时间 |
| 已放量，但持仓/多空比不达标 | 持仓条件不满足 | 已放量N倍；未通过完整条件 |
| 下一小时技术确认失败 | 未通过后续确认 | 触发区间 |
| 缺数据 | 数据不足，暂不能确认/判断 | 对应事件有补采信息时显示具体缺项和真实队列状态；不一概写正在补齐 |
| 缺同一目标小时的检查证据 | 本轮未检查 | 不得因有历史事件而假设本轮已检查 |

常规主表不展示旧失败、更正记录的红色主状态。历史通过记录仅作为一行辅助信息；更正和失败过程进入详情。全页统一标注最近扫描检查小时、北京时间；若检查目标落后当前一个小时以上，显示“尚未更新至当前小时”，不称实时行情。

## 三、严格时间规则

固定目标收盘为T。最新检查根为[T−1h,T)，确认根为[T−1h,T)，因此本轮刚确认的触发根必须是[T−2h,T−1h)。最近一条历史事件、不同目标观察记录、超过T后才获得的确认都不能代替这两个精确小时。

本轮事件必须绑定同一target_close_boundary；只凭日期接近不能充当本轮确认。若同一轮既有前小时完整确认，又有最新小时新触发，主状态优先显示完整确认，同时“本轮已放量”筛选仍保留最新小时是否技术触发的独立布尔值，并在详情/原始证据保留两者；不得凭优先显示丢弃任意事件。

21:00—22:00触发，在22:00后识别；22:00—23:00为确认小时，最早23:00收盘完成确认。触发开始、确认收盘、首次发现时间分别保留。历史补算或监测开始后延迟发现均不能称刚出现；详情显示实际首次发现时间，不用historical=false声称实时发现。

## 四、筛选入口与兼容

1. “本轮信号”：默认选“本轮有触发或确认记录”，包含放量后资格失败的记录，避免ALT消失而用户误以为未采集。可进一步选择已放量、已确认、等待确认、数据不足、条件失败、未检查、无新信号。
2. “历史信号”：清楚标注历史查询；原complete/pending/unknown等筛选值保留，前缀改为“历史”。原组合、保存条件和链接不悄悄变成本轮语义。
3. 新增cur_*筛选值，只是前端查询条件，不写入策略注册表，不改规则。历史来源范围仍适用于历史查询；本轮查询不以“历史补算/前向”筛掉本轮观察证据。
4. 主表显示的“上次确认信号”查找真正完整通过的最近事件，不以最近事件时间冒充确认时间。该时间指触发小时开始；确认收盘在详情另列。
5. CSV原字段、历史事件、修订和完整载荷均保留，新增查询结果通过B_round对象和raw.B_round保留目标、状态、选定本轮事件、最新小时技术触发标记和最近历史确认记录，不删除任何原始数据。
