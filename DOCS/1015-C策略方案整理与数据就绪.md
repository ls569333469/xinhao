## 3. 原策略规则：保持不变

### 3.1 C0候选

在同一精确合约、同一闭合4H根，以下五项全部通过才建立正式C0：

1. Wilder RSI(14) **<25**。
2. 收盘价严格低于EMA7、EMA25、EMA99全部三线。
3. 有效同期OI / 可信流通市值 **>30%**。
4. 有效同期全体账户LSR **<1.5**，不换成大户账户比或持仓比。
5. 最近14根连续4H严格收盘新低 **≤2**；窗口截至本根，首根作基准，其后严格低于窗口内此前全部收盘才计一次。

T0固定；等待期重复超卖不刷新。新低必须重新使用完整14根窗口计算，不能在A的10根计数上简单补4次，也不能只从入池之后开始累计。输入不足或中间断根属于未知。

### 3.2 C1确认

- 仅T+1～T+10，含T+10、不含T0。T+1指紧接T0的真实下一根4H，不指下一次扫描。
- 确认根计价成交额 / 此前7根同口径4H均值 **>3**，且收盘 **>开盘**。分母不包含确认根；零分母或缺根未知。
- 确认时仍须OI/可信市值>30%、LSR<1.5、最近14根严格收盘新低≤2；不再要求RSI<25或仍在三线下方。
- 明确失效先于确认。同一周期最多一次确认；理论最早参考入场为C1后下一根4H开盘，不代表已成交。
- T0同根确认是独立研究变体，首批不同时上线。

### 3.3 失效、到期和重武装

- 最近14根严格收盘新低≥3，明确失效。
- 两根**真实相邻闭合4H**均有有效LSR且≥1.5，明确失效；单根≥1.5只保留候选，该根不能确认。1.6→1.4→1.7不构成连续失效。
- 缺LSR不能拼接前后两个高值；未知不等于已恢复。后来补到缺失根须重新逐根判断。
- T+10依次检查失效、有效确认；仍未确认则到期。T+11不确认旧周期。寿命按真实4H边界计，不因缺数暂停、不按“成功取到的10根”计。
- 到期主原因固定`expiry_10_bars`，另列`missing_lsr/missing_oi/missing_cap/missing_candles`与未放量等原因。允许确认区间有缺证据时，显示“到期，部分时段未核验”，不能声称全部时段都不满足。
- 确认/失效/到期后，须先观察到完整C0资格明确不满足，再重新满足才重武装；未知不能完成这一步。持久保存武装状态及对应证据，不靠页面或进程内变量。

### 3.4 原模拟退出：另行实施

入场后闭合4H收盘<实际研究入场价×0.85，或该根4H量比<1，触发后以下一根开盘作退出参考；等号不触发。多原因全部保留，主原因止损优先；缺量不阻止有效价格条件。

只检查入场后的根。15%是触发参考，不是亏损上限。首批只做信号观察，不因本稿启用模拟仓或真实交易。

## 5. 同期证据契约与补齐方式

### 5.1 统一时钟

目标根收盘边界`t=open_time+14_400_000`，UTC毫秒。币安`close_time`通常为`t-1ms`；不能混用这1ms差异判断是否闭合。页面显示北京时间，图表开盘标签与实际收盘时刻分开。

OI/LSR沿v3.1的B/C研究门禁：样本有效时点`s`须满足`0≤t-s≤300000ms`。来源若给桶起点，先依据来源契约确定实际有效时点；不清楚则未知。`period=4h`只是请求参数，不能自动证明样本符合目标收盘。`s>t`、过旧或单位未知不作为经济条件fail，而记证据unknown。

分别保存`source_effective_at/source_available_at/retrieved_at/first_seen_at`、来源、period、单位、原样本与hash。同期不等于当时可得；事后才取得的真实同期样本可以更正历史结论，不能冒充实时发现。

### 5.2 分来源取得及质量门禁

| 来源 | 如何补齐 | 不允许的替代 |
|---|---|---|
| 4H K线 | 先读现有归档/共享引用和区间合并索引，按缺根分页补；固定算法、输入范围及版本 | 用最新指标判历史、只看首尾、多读少存冒充全覆盖 |
| OI | 复用来源适配器和已有历史样本；按每个目标4H边界选同期样本，币本位保留乘数，需换算时绑定同期价格 | 用当前OI回填旧根、原生数量直接当美元 |
| LSR | 归档可得历史序列，逐4H边界选有效全体账户比；保存实际样本时间和有效性 | 用两次扫描末值代替相邻4H、用较晚样本补早时点 |
| 流通市值 | 复用可信资产映射、新鲜度与历史证据适配器，绑定该时点供应商记录/修订 | 同名币映射、当前市值倒填历史、仅非空就算合格 |

市值新鲜度沿现有可信门禁，C实现契约须显式写出实际值和来源。本次核对B历史适配器为`capTrusted=true`且`0≤t-capObservedAt≤1小时`；建议C首版复用该可核验条件并以独立`evidence_profile`固定，**不是擅自修改A或放宽市值时效**。如实施前发现依据/运行版本不同，先记录并审定，不能默选。

各必需项采用pass/fail/unknown；任何已知经济条件fail优先，无fail但有unknown则整体unknown，全部pass才完整资格通过。C0技术项通过但结构证据未知，可保存“超卖条件出现，资格待核验”的技术观察，不能建立已合格C0或计入完整候选数。晚补后从最早受影响根回放，才确定历史T0。

**复用适配器，不直接复用B策略判断。** `b_evidence.structure_at`目前硬编码LSR<0.80和1h来源标记，C要求<1.5，不能直接调用后换标题。应抽取参数明确的通用来源选择/质量工具，C资格函数独立；保留B原输出基线并回归验证。

### 5.3 来源阻塞

缺项建持久gap，保存合约、来源、边界、原因、尝试次数、下次可重试时间和continuation。401/402/权限不足标blocked并提示所需权限/额度；429/418按共享限速退避；历史窗口超限标超限，寻找已归档来源，无法恢复则明确不可核验。

不可恢复不等于指标不满足。不得无限忙重试、把unknown填0、用未来数据替代，或通过改阈值“清零待验证”。来源恢复后继续原缺口，不重新清空缓存预热。

## 6. 数据保护、增量与中断恢复

1. **保护现有1H与A/B资料**：本次C接入不清空1H、不迁走B事件、不删除失败/未知样本。实施前保存全部现存1H逻辑键和payload hash、B事件修订、A候选基线与一致备份；迁移后逐键比对，真实源修订另存版本而非冒充丢失。
2. **一次读取多处使用**：同合约同周期共享必需输入窗口，供C周期和活动追踪复用；不对每个信号重新请求、解压全段历史。14根新低、前7根量能与EMA/RSI预热分别核验。
3. **固定边界和持久待办**：当前任务目标不滚动；新闭合边界记录新demand，任务复用按市场/合约/周期/规则版本/目标身份判断，不吞掉新目标。
4. **按真实根连续推进**：从最后连续评价根逐根处理，中断4小时、48小时、超过单页上限均分页恢复；预算耗尽保留待办。不能只拿最新1500根就宣称更早区间补齐。
5. **分水位**：下载最大时点、连续归档水位、C规则已连续评价水位、追踪水位分别保存；OI、LSR、市值各自记录缺口，不用max覆盖慢来源。任务success不等于目标小时/4H全覆盖。
6. **失效不能被跳过**：离线期间先跌破再恢复，必须在真实失效根结束原观察；末根恢复不能证明中间始终有效。缺K线时保留未知，不能跨缺口确认连续LSR或新低窗口。
7. **寿命与评价分开**：即使缺数，T+10现实边界仍到期，但保存未核验区间；不能越过缺口宣布全部10根已审完。后来补齐按顺序产生有修订关系的历史确认/失效，保留旧到期记录，不伪造实时通知或成交。
8. **持久可恢复**：事件、状态转换、已评价cursor、通知outbox同库事务；写入失败不推进cursor。Windows占用采取短连接、受限重试，磁盘满/损坏引用明确失败，保留上一有效结果，不发布假“已保存”。

EMA/RSI复现必须保存初始化方法、窗口起点/根数、规则版本和输入hash；不能静默把原1499根窗口改成全上市历史后仍声称原规则结果不变。已有归档足够的部分先离线复用，需要补采的区间单独列清。

## 7. C周期与持续追踪分开

### 7.1 三个状态维度

| 维度 | 建议状态 | 含义 |
|---|---|---|
| 原策略周期 | waiting / confirmed / invalidated / expired | T0、原确认窗口和原失效事实；历史修订另留版本 |
| 后续观察 | observing / ended | 是否仍主动追踪该事件走势，不等于仍有入场资格 |
| 数据质量 | ready / awaiting_data / stale / blocked / unrecoverable | 更新截至哪根、缺什么、是否可补 |

同一事件“原周期已到期，后续观察中”合法。“已确认，后来结构破坏”也合法，不能把它改成从未确认。`not_connected`仍是模块状态，不能伪装成某个币的fail。

### 7.2 送审追踪默认值：尚未启用

用户要求信号形成后持续跟踪、走势破坏可放弃。建议首版不设16小时/一周自动删除期限，按下列独立`tracking_profile_version`处理：

- 完整C0形成即建观察；等待期同时运行原C周期。数据未知只暂停相应判断并补数，不作为走势破坏。
- **C1确认后**，固定`cycle_low=min(T0至C1所有真实4H根的low)`作为本轮反弹结构参考；C1之后闭合4H收盘严格低于该低点则结束观察，等于不结束。计算窗口缺根时参考未知，先补齐。
- **未确认且到期**，原周期如实expired；技术观察可延续，以T0真实low为固定参考，后续闭合4H收盘严格跌破则结束。原窗口外反弹记“后续反弹”，不冒充原C1。
- **原周期明确失效**，首版建议结束该周期对应观察，保存失效原因；新的完整C0仍须满足原重武装，不能自动续命。确认后的LSR变化仅作风险变化，不能把等待期失效规则未经审定直接套成持仓退出。
- 确认后RSI升高、价格回到三线上是正常反弹，不单独结束观察。人工结束、经核验退市可结束；目录请求失败不能当退市。
- 不因长时间无新触发删除记录。走势结构结束、人工结束、原确认失败、模拟退出分别显示。原15%/低量模拟退出规则保留，不与上述新观察低点规则互相替代。

以上低点及终止规则是**新增观察设计，不是v3.2既有C规则或已验证最优止损**。在C-P0规则冻结时逐项审定；没有完成审定和测试前，不把“持续跟踪”标为正式上线。

### 7.3 更正与再触发

来源修订可能改变T0、C1、中途失效或低点，按最早受影响根重放，追加更正轨迹并保留旧轨迹/提醒。人工结束持久保存，不因自动重放重新开启。原始信号真正被修订撤销、旧周期结束后新触发、后续价格恢复是三件事，身份与文案分别保存。

历史导入不把所有旧事件标active，不批量弹“刚触发”。先逐根回放至可得边界，结束的归历史、仍有效的标历史形成、缺中段的待补；首次发现不刷新成今天。A/B也在观察时不能抢占或覆盖C身份。

| c_cycles / c_cycle_revisions | market/symbol/rule_version、稳定cycle_id、T0、预期T+10边界、C1、失效/到期原因、重武装及源版本 |
| signal_facts / evidence_refs | 技术与完整资格结果、原始OHLC/量能引用、14根计数证据、EMA/RSI预热和OI/LSR/市值时点/质量 |
| tracking_sessions / transitions | tracking_profile、低点参考、每次真实状态变化、结束根、人工标记、修订关联 |
| cursors / source_gaps | 各源覆盖、连续评价根、缺口、重试与分页continuation |
| notification_outbox / source_inbox | 通知去重、投递ACK和已读分离；来源修订幂等接收 |

事件身份包含市场、精确合约、策略、规则版本和T0根；同一根重扫不重建。首次发现、真实发生时间和首次确认发现分别保存。如重放纠正T0，保留旧身份并建立supersedes关联，不能静默改主键抹掉审计链。

C周期、修订、追踪转换、评价cursor、inbox消费和outbox在同库事务内提交。跨源库输入复用源outbox→tracker inbox→ACK机制，不将两个数据库双写称为原子操作；B修订输入通道与其原规则保持兼容。

### 8.2 单根处理顺序

```text
固定目标边界；读取版本、武装状态、连续cursor及未决缺口
取得必需输入及同期来源，验证根身份/连续性/单位/质量
按真实4H边界升序：
    更新来源质量；缺口持久化，禁止拼接断根
    对既有waiting周期先查明确失效
    未失效且处于T+1..T+10时检查完整C1
    到T+10仍未确认则记录到期，并保留未核验原因
    推进独立后续观察，不改写原确认事实
    按完整C0资格证据更新重武装；允许时建立新T0
    同事务保存状态/修订/cursor/outbox；失败回滚
```

同根终止后能否新建周期，必须服从此前已证实的重新武装状态；不能在终止根无条件重建。缺输入允许记录可核验的局部事实，但综合连续评价水位不得越过未决根。晚到来源触发历史重放，不只刷新最新摘要。

## 9. 页面、API、导出和提醒

- C未完成正式链路前继续“未接入”。只有快照字段/纯函数的阶段称“当前条件筛查”，不能称“正在持续观察”。
- 正式主表短文案：“超卖反弹观察”“反弹已确认，持续跟踪”“原确认已到期，继续观察”“反弹结构已破坏”“数据待补，判断暂停”。技术条件与完整资格分列，不能只写“可以买”。
- 显示4H周期、T0形成时间、确认时间、最后检查到哪根、当前数据是否陈旧和结束原因。细节展开14根新低、前7根量能、同期OI/市值/LSR与缺口。
- 当前值、触发时资格、当轮结果和补证据后修订结果分别呈现。事件数、合约数、本轮新增、活动观察数、未知数标清分母。
- 主表只返回紧凑摘要，详情时间线分页；不塞全轨迹、全K线背景进summary。列表、详情、CSV、报告共用后端状态和generation，完整证据可按引用展开。
- 项目内提醒由状态变化产生并持久去重：新C0、C1、后续反弹、结构破坏、缺数据/恢复；重扫不重复，历史补确认标延迟。送达ACK和用户已读分开，不在本稿接外部消息或自动交易。
- 当前scan/observe开关保持原状。已有数据可离线重放；行情不更新时显示“等待行情更新，检查截至……”，不能因页面开着就声称后台持续监测。正式前向验收另记录已获授权的运行范围、时段和驱动。
