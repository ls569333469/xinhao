## 六项口径

1. OI使用名义USD价值。USDⓈ-M以数量乘标记价格，COIN-M以张数乘合约面值。OI不是保证金，每份合约都有多空双方，不能由该比例推算强平规模。30%/50%是未回测的初筛参数，低于30%也可能出现异动。另展示同资产币安各合约的OI汇总，绝非全市场汇总。
2. 默认全体账户数多空比。大户账户比与大户持仓比在核心候选上补查，分栏显示。账户比0.57意味着空头账户约为多头1.75倍，并不能得知资金规模，账户比并不天然更准确。
3. 简单年化=单期百分比×24/结算小时×365。−0.14%/8h对应每天−0.42%、年化−153.3%；不是每天1.1%。4h费率每天6期，8h每天3期。当前值、实际已结算记录、周期来源分开显示。不能据负费率预测24–48小时必然上涨，极端费率先核查基差、费率上限、持仓集中和事件。
4. 固定已收盘4hK线，300根数据初始化EMA7/25/99。价格在三线下方表示受压，不证明底部或尚未启动。前一根收盘低于EMA99而新收盘上穿仅为线索，回踩守住、现货量、盘口、盈亏比仍需追加。300根初始化与全历史原生EMA可能略有差异。
5. 链上净流出暂未接入。需要精确资产、网络和可靠交易所地址标签，排除内部转账、跨链、托管及做市迁移。提币不证明买入或不打算卖出。缺失为未知，不计0或不命中。
6. 使用8个连续且不重叠的24h成交窗口：当前已结束窗口对比此前7窗均值，均在4h收盘边界对齐，价格变化也来自同一窗口。不用未结束日成交与完整历史日简单比较。3倍量且价格变动小于2%只是线索，可能是换手、对赌、卖出或分歧；合约量不能证明现货吸筹。

## 数据来源与项目映射

- Binance：exchangeInfo、ticker/24hr、premiumIndex、fundingInfo、openInterest、globalLongShortAccountRatio、4h klines。
- 候选复核：topLongShortAccountRatio、topLongShortPositionRatio、fundingRate已结算记录。
- 市值：CoinGecko coins/list与coins/markets。市值接口分页限流时保留已取得数据，使用CoinPaprika并明确标注。
- 明确项目ID映射与唯一代码匹配分开。唯一代码匹配并不代表已经核验链上合约；重名、价格差超过20%及非普通加密资产优先保留为待核对，不强行匹配。
- OI、账户比、市值和K线各自有源时间戳。OI超过10分钟或市值超过60分钟提示陈旧，但这些时限仍是可调整的规则，不是市场规律。

## 面板与报告

页面支持全市场筛选、可调阈值、证据展开、CSV导出和模板B证据报告。报告正文只使用已经取得的字段；基础设施没有额外接入LLM调用，AI核验和解读由当前对话完成，不冒充自动模型报告服务。

六项指标可独立勾选，组合支持全部满足（AND）、任意满足（OR）和至少满足N项；不勾选指标不限制指标命中。卡片命中数按名称、市场、市值和映射范围独立统计，不随其他指标勾选改变。命中项数排序按全部六项已确认命中计数，未知不计为未命中。

流通市值支持快捷范围及自定义，输入单位为万美元，最低值包含、最高值不包含。市值范围相邻不重复；缺失市值不进入明确命中结果。可只看明确项目映射。所有组合采用三态逻辑：明确满足、明确不满足、数据不足；例如AND中已有一项明确不满足时可排除，OR中已有一项明确满足时可保留，其余未知是否足以改变结果则进入“数据不足待核验”视图。第五项目前始终未知。

排序支持命中项数、流通市值、OI/市值、账户比、费率年化、量倍数、24h成交额、涨跌幅，均可升降序；缺失值始终排最后，同值按成交额降序、合约身份排序。所有筛选在浏览器localStorage保存，刷新后恢复；重置恢复不限制指标/市值、命中项数降序。合约详情以市场+合约代码识别。

CSV导出当前视图完整结果及顺序，附六项命中/未知状态、阈值、筛选条件和采样时间。汇总报告包含同一视图全部名单及前20份详细证据；待核验视图导出明确标记为待核验。`node verify-filters.cjs` 可离线检查本次快照计数、三态组合、市值边界和排序。

仅①②③满足为“杠杆异动候选”；④收盘上穿且量能增加为“突破线索”，不直接给买入指令。⑤⑥只是补充证据。绝不把六指标叠加解释为五星胜率、确认吸筹或确认内幕交易。

手动区间行情补查已在V2.7实现；后续按统一需求增加统一价格索引、可靠链上来源、现货量验证和结构化LLM报告；不需要高频AI调用。首次计划默认关闭；没有自动下单能力。
