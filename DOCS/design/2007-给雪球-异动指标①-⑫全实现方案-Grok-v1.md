## 2. 与币安 AI 说法的差异（诚实对照）

币安 AI 声称：①②③④⑥⑧⑨⑩ 可用 binance-pro-cli 自动拉；⑦⑪⑫ 第三方；⑤ 要 CryptoQuant。

| 说法 | 我们架构事实 | 判定 |
|---|---|---|
| ①②③④ 币安可拉 | 已在 `scanner.py` 用 **Binance public REST**（非必须 pro-cli）；市值来自 CoinGecko 等 | **基本成立**；工具名换成 cli 不增加新语义 |
| ⑥ 币安可拉 | 量倍数已由 4h K 线本地算；**若指量/OI**，oi+volume 也可本地算，但**尚未实现为指标** | **量倍数成立**；**量/OI 被顺口绑在⑥上会误导** |
| ⑧⑨ 币安可拉 | 公共接口具备原料；**工作台未接**；全市场扫描需节流/归档 | **方向对，状态夸成「已能自动」** |
| ⑩ 币安可拉 | **错误/过度包装**。币安衍生品 API 无「交易所地址标签净流」。Clawby Analyze「Net inflow」常是 **taker 差**，不是链上净流（见精准⑤方案） | **高风险误接**；禁止当精确⑤/⑩ |
| ⑤ = CryptoQuant | 与 [`给雪球-精准净流入补数方案-Grok-v1.md`](2008-给雪球-精准净流入补数方案-Grok-v1.md) 路径 B 一致；Basic 通常 **不含** on-chain | **方向对**；填 Key ≠ 已接入；须 EXT 授权 |
| ⑦ = Coinglass | 热力图/清算图是 Coinglass（或同类）产品能力；币安强平单 ≠ 热力图 | **第三方正确**；「有强平 API」不能冒充⑦ |
| ⑪⑫ 第三方 | 正确 | **成立** |
| 「自动拉」覆盖全表 | 588 合约量级下，⑧⑨ 逐合约 + 现货对齐有配额与耗时；⑦⑪⑫ 按资产覆盖远小于合约数 | **低估工程与 unknown 比例** |

**架构提醒**：本仓扫描器注释写明 *Read-only Binance perpetual evidence scanner*；指标进 `strategy-registry.json` 才进六项命中；旁路进 optional 列。**禁止**为凑 ⑫ 项把代理值写进 I5 或把 ⑩ 与 ⑤ 混槽。

## 6. 分项说明书（数据源 · Key · 模块 · 验收 · 不做）

### ① OI/MCap — 已有可算

- **数据源**：Binance `openInterest` + 标记价/合约乘数；流通市值 CoinGecko（缺则 Paprika/Alpha，已标来源）
- **Key**：市值源按现有扫描配置；币安公共行情一般无需交易 Key
- **模块**：已有 `scanner.py`、`strategy_registry.py`、表列 `oi`；无需为「有①」再开发
- **验收**：`oiCapPct` 与 `oiUsd/capUsd` 一致；无市值→① unknown；同资产汇总不进 I1
- **不做**：把全市场多所 OI 当币安单合约；用 OI 当保证金/强平规模

### ② 多空比 — 已有可算

- **数据源**：`/futures/data/globalLongShortAccountRatio`
- **Key**：无
- **模块**：已有；enrich 大户比保持分栏
- **验收**：I2 只读 `accountRatio`；缺数→unknown
- **不做**：用大户比替代全体；推断「空头资金更多」

### ③ 资金费率 — 已有可算

- **数据源**：`premiumIndex` + `fundingInfo` + 可选结算历史
- **Key**：无
- **模块**：已有年化与 `fundingIntervalStatus` 门禁
- **验收**：周期未核验时 I3 不得 true/false
- **不做**：把简单年化当已实现资金费盈亏

### ④ EMA 位置 — 已有可算

- **数据源**：已收盘 4h K 线本地 EMA7/25/99
- **Key**：无
- **模块**：已有；STRUCT/上穿为时机线索
- **验收**：只用已收盘；缺口 K 线不算 EMA
- **不做**：三线下方 = 底部；未收盘 K 触发

### ⑤ 精确净流 — 未接精确（Codex 主路径）

- **数据源**：见精准方案（CryptoQuant / Santiment Max / 探测后的 Clawby 等）
- **Key**：`.env` 已占位；有 Key ≠ 接入
- **模块**：未来 `chainFlowUsd`；`ext_store` 授权；**改 I5 仅在授权后**
- **验收**：无覆盖=未知；禁止 0 填充；reserves 声称精确→409
- **不做**：本文件不实施；不标 A 档完成；不用「二手日历」表述解锁

### ⑥ 观察窗量倍数 — 已有可算（量/OI 另议）

- **数据源**：4h 成交额切窗
- **Key**：无
- **模块**：I6 `volumeRatio` + `priceChangeWindowPct`
- **验收**：与存档窗口量/基准量一致（审计已有回归）
- **不做**：把单次量增价平写成吸筹；**擅自把 I6 改成 volume/OI**
- **若要 ⑥b 量/OI**：新字段如 `volumeOiRatio` = `volumeWindowUsd / oiUsd`（单位与窗口写死）；独立 optional / 未来 I 编号；阈值另定；单测与 I6 隔离

### ⑦ 清算热力图 — 需第三方

- **数据源**：Coinglass Liquidation Heatmap API（或官方导出）；币安 `allForceOrders` **仅作弱旁证事件流**
- **Key**：要（Coinglass）；写入 `.env` 新变量，例 `COINGLASS_API_KEY=`（先 example 空模板）
- **改哪些模块**（实施时，非本文件执行）：新建只读适配器如 `liquidation_heatmap.py` → `runtime/liquidation-heatmap/{asset}.json`；详情抽屉/时机层展示；**不进**六项 `signals` 计数
- **验收**：有图/有峰值价位 + asOf；无 Key/无覆盖→「未取得」；不得用少量 forceOrders 画假热力
- **不做**：全 588 合约强行热力；把清算簇当自动开多信号

### ⑧ Perp/Spot Volume Ratio — 未接，币安可算（P0）

- **数据源**：合约 `volume24Usd`（或同窗 quote volume）÷ 现货同资产 USDT 对 `quoteVolume`（`api.binance.com`）；无现货对→unknown
- **Key**：无
- **改哪些模块**：`scanner.py` 或旁路 enrich；行字段 `perpSpotVolRatio`；`pro-table-runtime.js` optional 列；`coverage_gate` 可选登记；**默认不进 I1–I6**
- **验收**：有现货→有限正数；无现货/COIN-M 计价陷阱→unknown+原因；与手算 BTCUSDT 等抽样一致
- **不做**：把「合约量更大」直接当多头确认；跨报价单位硬比

### ⑨ CVD — 未接，币安可近似（P0）

- **数据源**：`GET /futures/data/takerBuySellVol`（或 kline `takerBuy*` 累加）；定义：`cvd = Σ(buyVol − sellVol)` 在固定窗（建议与观察窗对齐的 24h 或 4h×N）
- **Key**：无
- **改哪些模块**：enrich 写 `cvdWindow` / `cvdSlope`；optional 列；文档写「单所合约主动量差分，非多所现货 CVD」
- **验收**：窗长、单位（张或 USDT）写死；缺 period→unknown；与官方 taker 面板抽样同向
- **不做**：宣称「聪明钱 CVD」；用 CVD 替代⑤；静默填 0

### ⑩ Exchange Netflow — 与⑤合并治理

- **数据源**：同精确⑤供应商；**不是** binance-pro-cli
- **Key**：同⑤
- **模块**：**不要**新建平行写入；UI 若需「⑩」标签，映射到⑤字段并注明别名
- **验收**：不存在第二套与⑤矛盾的 netflow 真值
- **不做**：币安 AI 口径的「已自动拉⑩」

### ⑪ Top Holder % Change — 需第三方

- **数据源**：Nansen Token God Mode / 持仓接口；或 Etherscan（及对应链浏览器）Top Holders 快照差分；须固定「剔除交易所冷热钱包与合约自身」规则，否则噪音极大
- **Key**：要（Nansen 等）；Etherscan 高配额可能要 Pro
- **改哪些模块**：`holder_concentration.py` → 按 `asset`+`chain`+`tokenContract`；optional 列 `topHolderPct` / `topHolderPctDelta`；映射复用 `asset_identity` / `asset-mappings.json` 思路
- **验收**：无合约地址→unknown；交易所地址过滤规则文档化；禁止用单点刮取当全历史
- **不做**：扫全市场 525 资产无差别拉取（credits）；把「庄家增持」自动写进策略候选

### ⑫ Options Put/Call — 需第三方（BTC/ETH）

- **数据源**：Deribit `book_summary` / OI 按 put vs call 聚合；或专用期权数据商；币安期权若用，单独标「仅币安期权所」
