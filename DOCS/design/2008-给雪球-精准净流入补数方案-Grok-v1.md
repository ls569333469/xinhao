## 1. 目标（再短一句）

让 I5 / 精确⑤ 在有覆盖时能判 **true/false**，无覆盖保持 **unknown/null**；禁止用 0、储备差、盘口资金流冒充。

写入扫描表⑤ = 给覆盖到的行填 `chainFlowUsd`（USD 净流入，符号约定与供应商一致并写死），再在授权后让 I5 读这个字段。

### Clawby 单独说清楚（检索结论）

- 产品：给 AI agent 用的 **聚合数据中继**（`api.openclawby.com/api/relay`），一 Key 多接口；官网写免费领 Key。
- 目录里和「交易所」沾边的：**余额**（`exchange_balance_list` / `exchange_balance_chart`）、**ERC-20 交易所大额转账列表**（`exchange_chain_tx_list`）、**地址标签**（`address_*`）、衍生品 taker 量。
- Analyze 页「Net inflow」= **taker buy − taker sell**（盘口主动买卖），**不是** 地址标签链上净流入——写进精确⑤会口径错乱。
- 因此：Clawby **值得立刻用现有 Key 探测**；能不能进精确⑤，取决于探测结果是否真能还原「标签钱包净流」，而不是直接假定可用。

## 3. 推荐实现路径（按成本 / 可行性排序）

### 路径 A · 零增量费用先探（优先做）

1. 用已有 **`CLAWBY_API_KEY`** 调：`exchange_balance_chart`、`exchange_chain_tx_list`、地址标签相关接口；BTC/ETH + 1～2 个山寨。
2. 用已有 **`DUNE_API_KEY`** 找社区 CEX flow query，只读跑结果，对照口径。
3. **不写** `scanner.py` / 不改 I5 / 不授权 EXT。
4. 产出一页探测记录（接口名、字段、是否标签净流、覆盖币、缺口）。

**理由**：Key 已在、摩擦最低；先分清「可用 / 只能代理 / 完全不是」。

### 路径 B · 付费开箱净流（预算允许的主落地）

任选其一（优先顺序）：

1. **CryptoQuant Professional**：REST 直接有 `exchange-flows/netflow`，最贴 `chainFlowUsd`；Basic/Advanced **拿不到** on-chain。
2. **Santiment Max**：项目历史管线已写好，升级后把同一套 metric 从「仅历史」扩到 live（注意 slug 映射、USD 用供应商 `_usd`，不要现价重乘）。
3. **Arkham Trial → 付费**：`/flow/entity/binance` 这类实体流做交叉验证或第二源。

**理由**：要的是「标签净流时间序列」，这三家是文档里写得最直白的；Glassnode 太贵，不主推。

### 路径 C · 自建（时间换钱，精度自负）

- 公开标签列表（如 eth-labels / etherscan-labels 刮取）+ 自有 RPC / Bitquery transfers + 自算净流；或 Dune/Flipside SQL 固化。
- **理由**：长期可控；短期标签不全、存款地址漏标、多链成本高——**默认达不到精确⑤授权门槛**，除非雪球接受「覆盖子集 + 明确未知」。

### 明确不主推 / 不够格

| 对象 | 原因 |
|---|---|
| DefiLlama CEX / `cex_reserves` | 储备变化 ≠ 精确标签净流；EXT 已禁代精确⑤ |
| Clawby Analyze Money Flows / taker 量 | 盘口资金流，不是链上交易所钱包净流 |
| Whale Alert 单独 | 事件告警，不是稳定净流序列 |
| The Graph 默认 subgraph | DEX 场景，不解决 CEX 标签净流 |
| Glassnode Advanced Light | 配额/历史不够扫全表；Professional 成本过高 |
| Nansen smart-money/netflow | 聪明钱买卖净流，不是 CEX 地址净流 |
| 免费 Santiment | 30 天滞后，写不进「当前」扫描行 |

## 4. 分阶段落地（接到扫描表⑤）

### 阶段 0 · 探测（1～2 天，可停）

- **做**：Clawby +（可选）Dune 只读探测；写 `DOCS/design/clawby-dune-probe-YYYYMMDD.md`（可附 raw JSON 到 `runtime/`，**禁止**把 Key 写进文档）。
- **不做**：改 `scanner.py`、改 I5、授权 `precise_indicator_5`。
- **通过标准**：说清楚「有没有标签净流字段 / 覆盖哪些币 / 时区与符号约定 / 要不要付钱」。
- **失败**：停在阶段 0，精确⑤继续未知。

### 阶段 1 · 选源 + 口径纸（0.5～1 天）

写清一页「精确⑤口径」：

- 供应商、endpoint、净流入符号（建议：`net = inflow − outflow`，负=净流出，与现有 `chain_flow.py` 一致）
- USD 来源（供应商 USD，禁止现价硬乘）
- 时间窗（建议先 24h 或 1d UTC 完整日）
- 覆盖资产映射（显式 slug/asset id，禁止 ticker 模糊搜）
- 无数据 → `null` + unknown，禁止填 0

选定路径 B 的一家（或探测证明 Clawby 真够格再走 Clawby）。

### 阶段 2 · 只读适配器（不碰信号）

- 新建例如 `precise_chain_flow.py`（名字随意）：拉数 → 规范化 → 落 `runtime/precise-chain-flows.json`。
- **仍不写** live `scan.json` 的 `chainFlowUsd`，或只写旁路文件对照。
- 单测：缺 Key / 403 / 半截序列 → 该资产失败进 failures，不冒充 0。

### 阶段 3 · 接到扫描表⑤

- 在扫描合并步骤：仅当资产在「精确覆盖集」且数值合法时写入 `chainFlowUsd`；否则保持 `None`，`chainStatus` 说明原因。
- `scan_verification` 继续：无效 `chainFlowUsd` 不算覆盖。
- **仍不改** I5 规则，直到阶段 4。

### 阶段 4 · 授权精确⑤ + 打开 I5（单独门禁）

- EXT：`precise_indicator_5` 走正式授权（echo / gates），禁止 reserves 冒充。
- `strategy-registry.json` I5：从 `op:unknown` 改为基于 `chainFlowUsd`（或净流出阈值）的真实规则——**仅在授权后**。
- 页面继续：无覆盖显示未知，不显示假 0。

### 阶段 5 · 观测，不标 A 档完成

- 抽 10～20 个有覆盖币人工对一下供应商面板。
- 全表覆盖率预期会远小于 588；其余保持未知是正确行为。
- **明确：本方案落地 ≠ A 档完成。**
