2. 共用模板去除 STRK 的 127m/163m 案例数字。解锁子集/总量、流通/总供应、解锁/转所/实际卖出分别核实；案例留在经验文档。
3. “保存提示词”改为持久化标准模板，使用现有配置 hash 防覆盖。后台直接新建也读取保存的标准模板；固定证据规则保持独立。报告保留实际输入、版本与 hash。
4. 沿用现有模型与 Key，通过明确的 `/responses` + `web_search` 做取证，再按已配置协议（当前 chat）调用同一模型成文。检索协议与成文协议分别记录，不改全局配置，不要求另选搜索服务。
5. 默认每组最多 5 币：要求检索时计划 2 次模型请求（检索+成文），否则 1 次。预览显示实际计划总请求数；每次检索 `max_tool_calls=6`。只有明确 429 有界退避；超时/断连保留“结果未知/可能计费”，不自动重发。不承诺工具内部搜索和供应商绝不重复扣费。
6. 联网判据必须包含完成的 `web_search_call` 与实际返回来源、检索摘要。单有模型正文或网址不够。完整返回原包与工具记录落盘，URL+摘要生成独立证据 ID，冻结后交给成文模型。未返回实际工具和来源则停止成文，不换渠道、不偷偷追加收费测试。
7. 模型检索摘要标记 `search_summary`，不冒充已抓取原文/逐条人工核验。每币来源支持度、日期与催化充分性仍需内容核验；不得标“全网穷尽”。本轮 `online_verified=false`，实际取证另外显示 `actual_search_performed`。
8. 结构/自动校验失败仍保存收费输出、供应商原包与提示词，但任务标失败，不计成功，不进入策略草案。客户端自行提交 excerpt 或从通用草案 API 伪装来源也不能绕过生产服务的门禁。转草案绑定原始版本 0；未经复核的人工修订版拒绝静默混用。
9. 只重试失败币仅包含普通失败；校验不合格与超时未知结果分别列出，不自动再次付费。重新生成不合格报告需重新预览并明确确认。成功与不合格报告都可查看，各自状态可追溯。
10. 旧报告保留原始校验，另加“当前规则复核原始版”展示，不改写历史文件。要求检索的新报告至少引用一条本轮登记的外部证据；引用存在仍不代表论点已得到来源支持。
11. 页面乱序响应、后台列表刷新不能替换用户后来选择的报告。编辑提示词/关注点/检索选项立即使预览失效，取消预览不建任务。
12. 静态页面若已更新、旧 Python 进程尚未加载新接口，投研提交显式停止，避免继续走旧 fixture 路径。部署状态必须区分源码、离线测试与运行进程。
