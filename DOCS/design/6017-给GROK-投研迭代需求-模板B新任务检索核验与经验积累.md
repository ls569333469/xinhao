## 1. 本轮目标与边界

让标准投研可以复用今天 STRK 报告的研究方法：重新取证、分清主次催化、核对时效和口径、输出可读报告，并留下可复查的证据与用量记录。仅替换一段提示词不能达到这个目标。

本轮应先完成标准投研主链：**独立确认 → 新任务 → 实际取证 → 冻结输入 → 新模型调用 → 核验 → 模板 B 正文 → 历史与导出 → 可追溯的策略草案**。经验库先沿用项目外文件与聊天反馈；页面化管理作为后续可选阶段。

本文件属于原 A 档“02 投研”深化，并核对其与 01 扫描、03 策略的接口；不借此扩展到 SIM/EVAL/REVIEW、自动交易、全市场历史回测或其他未授权实现。本文不自动授权收费测试、服务操作或计划任务。Codex 本次只写项目外文档，未改项目。

## 3. 用户流程：新投研、预览、历史各自明确

1. 用户选择实际市场/合约、范围、档位、数据模式、模板/关注点与检索选项。标准档默认模板 B，并默认尝试最新公开资料检索。
2. 预览列出投研对象、快照时间/版本、模板与用户编辑、拟执行的检索、覆盖缺口和可能的收费步骤。预览本身不调用收费模型；取消不创建投研任务。
3. 修改合约、筛选结果所对应的投研对象、快照、模板、提示词、关注点、检索选项、模型配置等冻结输入后，旧预览失效，重新预览确认。后台版本变化也须拒绝陈旧预览，不能静默换配置。
4. 每次独立确认发起新任务；同一次点击的连点/网络重传保持幂等。执行中可排队，明确状态；不能因内容相同合并用户的第二次独立确认。
5. “扫描并投研”先执行本轮扫描、绑定新快照，再研究；扫描失败就显示失败，不回退旧快照。“当前快照投研”可以保留，但明确行情时点，不伪装成刚采集行情。
6. 标准投研重新获取本轮外部证据。当前快照模式下也要分别显示“行情快照时间”和“本轮新闻检索时间”，避免混成一个“最新”。明确选择只解读历史快照时，不声称完成最新研究。
7. 失败、部分覆盖、待核验都独立显示。旧报告仍可从历史打开；本次详情不得残留旧正文冒充成功。查看历史和重新生成是不同操作。

快速/深度档的完整改版不在本轮强制范围，但“独立确认必须新调用”“预览取消不收费”“不冒充已检索”等规则适用于所有档位。快速档若继续只读快照，在页面说明；不能把快照摘要称为完整最新投研。

### 3.1 去重与缓存身份

- 建议独立确认生成 `submission_id`/幂等键；同一次确认重传使用同一个键，第二次独立确认必须换键。该键绑定输入摘要，同键不同内容应冲突拒绝。
- `request_hash`、`evidence_hash`、`prompt_hash` 用于输入追溯、比较与完整性校验，不再单独决定复用收费结果或活跃任务。
- 对同一确认的状态恢复不能重复计费；对“已发给供应商但本地超时”的不确定状态如实记录，不能假装从未调用并无限重试。
- 历史报告和原始证据可以保存；新闻抓取缓存须有时效及重新验证策略，过期不能作为本轮已新取证。无需机械禁止任何 HTTP 缓存，但必须证明时间与覆盖符合本轮要求。
- 默认正确性不能依赖用户知道 `force=true`；也不能用 force 绕过配置版本/证据一致性保护。

## 4. 模板 B 与项目数据的结合

### 4.1 标准报告的八节

| B 章节 | 必须覆盖的研究内容 | 与项目已有数据的接线 |
|---|---|---|
| 核心催化剂 | 当前事件、主次、发布时间/事件时间、进展阶段与反证；没有可靠证据就说明未核验 | 外部证据 ID、官方公告/社交原文；不拿旧行情解释代替检索 |
| 价格与市场 | 当前价格/24h、流通市值/FDV/供应口径、成交与流动性；异常或缺失具体说明 | 实际合约身份、快照、报价单位、市值映射、独立成交窗口 |
| 风险与机会 | 利多≤3、风险≤4；解锁、估值、叙事、流动性等避免重复 | 区分已证实事实与推断，缺数据不当成无风险 |
| 技术面 | 周期、均线/EMA、RSI 等有效指标，简表加解释；数据不足不硬填 | K 线是否闭合、预热、算法/周期、可信 ATH 与区间高点 |
| 合约结构 | 资金费率及实际周期、OI、账户比和持仓比各自含义 | 六指标及阈值/三态、source/available_at、当前与历史窗口 |
| 基本面 | 产品/生态、供应机制、最新进度；收入/TVL 等有对照才评价变化 | 官方及可核验第三方资料，明确覆盖与口径 |
| 支撑压力 | 类型、区间、依据，约 2+2 档；无依据可以缺省 | 有版本的技术证据，时间周期，不编造精确点位 |
| 综合判断 | 主驱动、确认/失效条件与主要未知，短结论 | 状态、证据引用；策略候选/依赖另用结构化附件承接 |

正文保留普通用户读得懂的表述；六指标、满足/不满足/未知、规则版本、证据/策略依赖等不能因为模板 B 变得简洁而丢失，可放相应章节或可展开的结构化附件。

“默认 Binance USDT 永续”只用于未指定市场的默认解析；用户实际选择 USDC、币本位或其他交易所时，以明确合约为准。遇同 ticker、1000 倍合约或映射不确定，先确认资产映射，不按名字猜。

### 4.2 Schema、渲染与导出

- 版本化保存 B 正文结构与机器可读字段；推荐单一权威结构同时生成 UI/Markdown/导出，避免多份文本互相矛盾。具体字段名不强制。
- 保留事实、假设、反证、未知、确认/失效条件、证据引用与策略依赖。必须校验实际选中合约集合、非空报告、字段类型和引用存在性，不能空 contracts 仍标通过。
- 拒绝伪造/越界 evidence_id、合约串线、模型/模板身份矛盾；区分模型自述 metadata 与服务端冻结的真实身份，真实身份不得被模型覆盖。
- 多合约逐份可读，篮子总结与单合约分开；token 上限不足时应分批/提示范围，不能静默少币、截断后标整批成功。
- 报告列表遵守 §11.8：币名+投研报告/数据报告、时间；正文是阅读态，调试信息、长 ID、设计备注不塞标题或默认正文。来源与时点放短引用或可展开“来源与运行记录”，关键过期/缺失提示仍须可见。
- 本地数据报告不能标成 AI 投研。UI、导出与历史查看须保留同一报告版本；旧报告仍能打开，不用新模板回写旧证据。

## 5. 实际检索与证据规范

### 5.1 检索必须能被验证

标准档默认围绕本轮项目身份和研究时间重新检索：最新官方动态、关键催化、供应与近期解锁、必要的生态/基本面变化及竞争解释。时间范围和主题随项目调整，不硬编码每个币都查同一网站。

GROK 可选择检索适配器或供应商原生工具；必须保存真实工具/HTTP 结果、访问时点及证据。模型自称“已联网”、搜索复选框、鉴权成功、普通模型连接成功，都不构成检索通过。动态页面中的关键表格未加载，也不能仅凭外层页面 200 就标取得数据。

记录检索状态：成功、部分成功、失败、不支持、未启用、未验证，以及具体原因。关键催化查不到时，可以生成明确标注缺口的部分报告；不标完整最新投研，不捏造“没有新闻/没有解锁/没有风险”。不强制为检索、写作、核验各加一次 AI；按实际实现与成本取证。

### 5.2 每条关键证据的最小记录

| 内容 | 要求 |
|---|---|
| 身份 | evidence_id；交易所/市场/合约与底层资产映射；来源发布主体及官方归属依据 |
| 内容 | 原始摘录/结构化数值、原单位、币种、周期、覆盖范围；必要的本地留存与内容哈希 |
| 时间 | source_url、published_at、event_at（如有）、retrieved_at、available_at；时区未知就记未知 |
| 质量 | 官方原文/第三方/未核验，访问成功与字段取得情况，冲突/陈旧/缺失说明 |
| 使用 | 哪些结论引用该证据；本次冻结证据版本；生成后新增证据的独立版本 |

凭证不进提示词、报告、导出和公开审计包。外部内容只当证据，不执行其指令。来源时间、事件时间与检索时间不能混写；回测/历史研究不使用当时尚不可得的信息。

### 5.3 必须执行的口径检查

1. 区分“考虑、提案、通过、计划上线、已上线”。目标年份不是已批准迁移，预发布说明不是实际部署证明。
2. 数字冲突先查类别、区间、单位、时间、分母；未解决就保留冲突，不武断选一个。解锁子集不当全量、解锁不等于实际净卖出。
3. 当前价格/资金费率不能和旧指标混成一套现值；账户多空比与持仓比、单合约与全市场 OI、当前费率与历史结算分别处理。
4. 技术指标注明周期、闭合状态、算法及预热。异常 ATR=0、无标签 MACD 数组等不得强行解读；证据不足则省略或标未知。
5. 说“成交增长、OI 增加、TVL 下滑”要有同口径对照；单点数据只能描述当前。负费率、账户比偏低不能独立证明主力对冲。
6. 精确当前净流、交易所局部储备变化、历史净流分别展示，不能替代。历史净流保留来源与日期区间，必要时标明非当前⑤。
7. 六项条件不能推导必涨、主力吸筹确认或精确胜率；没有可验证统计样本不输出“胜率 61.5%”等数字。

## 6. 生成、复核与报告版本

建议按可观测阶段执行：准备对象/能力 → 扫描或读明确快照 → 检索与缺口检查 → 冻结输入 → 模型生成 → schema/事实/引用核验 → 发布报告及草案。

模型实际提交中必须包括用户编辑的提示词、关注点、选定模板版本、全部目标合约与本轮证据，不只是预览里显示。提交 payload、原始响应、解析结果及后处理版本可追溯，避免“显示改了，实际没送”。

生成后至少检查：数字和单位能回指证据、引用真实且支持结论、催化是否遗漏、时间是否过期、是否存在无依据增长/因果/精确胜率、选中合约是否完整。可用确定性校验与人工核验，必要时用额外模型；分别记录动作，不把所有校验都等同 AI 已完成。

原始模型输出和最终报告分别保存。生成后补查或人工修改须留下新增证据、修改原因、版本与核验者；不能反写初始输入，声称原模型看过补充材料。下游策略草案也绑定实际报告版本。

分别记录：真实模型调用成功、结构校验通过、检索取得证据、质量核验状态、用户页面验收。至少支持“待核验/部分通过/通过/失败”之类等效状态，不能一个 success 覆盖全部。超时、输出截断或关键字段无效不能发布为完整通过。

## 7. 与扫描、策略的接口收口

- 扫描本身是行情采集与规则筛选，不天然需要 AI；“扫描”“扫描后投研”分别记任务阶段与实际调用数，不能默认每个扫描动作都收费。
- 已选页签、投研对象、预览数量和实际提交合约必须一致。筛选/分页后保留的选择须有稳定身份，不能只提交当前页或误用另一份 rows。
- 当前快照与扫描并投研分别绑定 scan_id/revision/evidence_hash；扫描失败不能悄悄使用旧数据。范围变更后重新预览。
- 策略建议只是研究候选，不代表自动启用。报告中的建议应能生成带证据/依赖 ID 的草案；无建议可为 0，但要说明原因，不能拿几段 prose 视为链路已通。
- 缺关键数据/规则映射时保留待补草案或拒绝冻结/启用；冻结规则不可原位修改，新增版本。导出/导入保留身份和覆盖指纹，缺字段/篡改/过期指纹拒绝且无半成品。
- 不以本轮研究改版弱化原 A-03 的冻结、版本冲突、依赖与覆盖硬闸。执行、撮合与实盘后置。

## 8. 实际调用、token 与成本记录

每个任务记录实际模型请求次数，并逐次区分检索规划、生成、核验、修复、重试等步骤。每次包含模型/供应商、开始/结束时间、结果、重试关联、供应商 request_id（若有）与实际 usage。失败请求也保留是否可能计费，不能只统计最后成功的一次。

input/output/total 按供应商定义统计；reasoning 若包含在 output/total 内就不能重复相加。未返回 usage 则显示未知，允许另列估算但不得称账单。金额须有可核验价目/计费规则及币种；未知就不编。

STRK 独立样本：供应商模型 `gpt-6.1-sol` 实际请求 **1 次**，无重试/缓存；input **3396**、output **2807**、total **6203** token；reasoning **516** 已包含在输出/总量内；供应商请求耗时约 **93 秒**。这不包括 Codex 本聊天的网页检索、人工核验和改写成本，也不是未来每份报告的固定预算或“一次调用即可全自动完成”承诺。

另一次 PUMP/RATS 试跑是两份报告、共三次供应商请求（含一次超时及重试），不要与 STRK 一次混算。

### 9.2 接入评估与可选页面

积累约 3–5 个不同项目后，检查关键催化遗漏、无证据事实/因果、时间/单位错误、引用错误、人工修改量、时长与用量。长报告、更多链接不代表更好；出现反例要修订/停用。

后续可选“投研反馈与经验”页面流程：报告反馈 → 候选经验 → 审核/修改 → 采用/停用 → 下次任务记录实际应用的 ID/版本。可以自动提取候选，**不得未经明确审阅就改变生产投研规则或默认提示词**。历史案例不回写，新任务不自动继承旧数字。

页面化不列入本轮前置阻塞。未来接入时按适用条件选相关经验，初期每次约 3–5 条，记录选择依据；不要将整个库和全量历史报告塞进每次提示词。保留停用/回滚与版本追溯。
