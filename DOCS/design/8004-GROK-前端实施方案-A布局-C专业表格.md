## 3. 专业表格：信息不能减少

默认显示选择列、合约/价格列，以及以下 11 个数据列：

1. 流通市值。
2. 命中数 / 可算数 / 未知数，附六项状态。
3. 本合约 OI（美元）。
4. ① OI / 市值。
5. ② 全体账户多空比。
6. ③ 当前资金费率 / 简单年化，附实际结算周期。
7. ④ 已收盘 4h 价格与三条 EMA 的关系。
8. ⑤ 净流入判定；缺精确来源时显示“未知 · 无精确覆盖”。
9. ⑥ 观察窗量倍数及相关价变。
10. 24h 涨跌。
11. 24h 成交额。

列配置支持 26 个数据列。其余 15 列为：大户账户比、大户持仓比、标记价格、指数价格、24h 最高、24h 最低、单根量倍数、观察窗成交额、基准窗成交额、EMA7、EMA25、EMA99、已收盘 4h 价格、同资产总 OI、观测时间。提供“专业默认列”和“全部数据列”快捷操作。

证据抽屉另保留完整字段，分为合约行情、衍生品、量价与均线、市值身份、同资产 OI、观测时间与限制。至少包括项目 ID、映射状态、市值来源/时间、OI/账户比/K 线时间、EMA 方法、覆盖和缺口。

- 缺失值显示未知及原因，不能变为 0 或 false。区分完整同资产 OI 与已收部分 OI；两者也不能替代本合约 OI。
- 命中数采用后端真实六指标结果，不能将“可算 5 项”显示为“命中 5 项”。
- 选择列和合约列固定，表头固定；数据区局部横向滚动，页面本身不横向溢出。
- 固定列偏移按实际列宽计算，避免横向滚动时叠在一起；底部托盘不能遮挡分页或最后一行。
- 缺失数值正序、反序均置后；同值采用稳定的合约身份排序。点击表头显示当前方向，并同步工具条。
- 列配置、筛选和选择变化保持一致；显示列可以持久化到本地，但凭证不得进入 localStorage。

## 4. 筛选与选币规则

使用正式扫描快照及现有统一策略注册表，禁止把预览内嵌数据或预设复制成生产常量。

| 场景 | 验收行为 |
|---|---|
| 市值区间 | 下限含、上限不含；自定义输入标明百万美元单位；非法范围提示并阻止应用 |
| 市值未知 | 单独进入待核验，不能硬塞进某个明确市值区间 |
| 六项统计 | 在搜索/市场/市值/映射基础范围内独立统计，不先受其他勾选指标筛掉 |
| AND | 任一 false 则不满足；全部 true 才满足；其余 unknown |
| OR | 任一 true 则满足；全部 false 才不满足；其余 unknown |
| 未勾选指标 | “明确满足”只表示满足基础筛选，不能解释为命中六项 |
| 组合预设 | 从统一注册表读取，与策略页同名同定义；候选筛选与执行入场规则分别说明 |
| 合约选择 | 以 market + symbol 稳定标识；跨分页、排序、筛选保留；同币不同市场不静默合并 |
| 本页全选 | 只选当前页；状态与托盘同步；不能不经说明变成全市场全选 |
| 快照更新 | 重核已选合约是否仍存在；失效对象提示并阻止未经核对的投研 |

预览使用的是历史快照，不是实时行情。该快照 588 份合约，在默认 1000万–5000万美元范围下有 181 份明确满足基础范围、73 份市值未知。这些数字只用于同一预览快照的回归，正式新扫描不得硬编码为验收结果。

## 5. 投研：显式对象、提示词与任务

投研页同时提供“使用扫描已选合约”和“指定代币”入口；未选币时也能直接输入指定代币。

指定代币先查询现有快照，展示资产名称、market、symbol、映射来源供核对。USDT 可以作为优先建议，但不能静默替用户决定身份。同名资产或多个合约必须显示选择；未找到则提示缺数据，提供受控补扫描或完整扫描入口，不能用虚构数据直接写报告。

快速 / 标准 / 深度的提示词从正式模板或后端预览读取：公共证据约束 + 对应深度任务 + 用户补充关注点。界面可以折叠，但用户应能看到实际将提交的任务。页面不要求填写 token 消耗预算，额度沿用节点后台配置。

提交分成可见的两个阶段：先预览对象/深度/模型/快照 ID 与 revision/证据缺口/缓存身份，再明确点击生成。预览后对象、深度、关注点或快照改变时，原预览失效并重新核对。

提供两种操作：

- 当前快照投研：明确使用哪个快照，缺口和过期状态可见。
- 扫描并投研：先生成新扫描，再用该任务对应的新快照研究；扫描失败不得退回旧快照，partial 按正式规则处理并明示。

任务中禁用重复提交，展示排队/扫描/分析/成功/部分成功/失败/取消状态；在途复用显示真实任务 ID。取消不能显示为成功。超时应提示任务仍在运行，允许去任务页查看，不能在浏览器超时后重新触发一份付费任务。

## 6. 报告阅读与 API 设置

- 报告列表采用“代币名 + 投研报告 + 时间”；多币报告标对象数量，正文明确对象身份。
- 显示真实报告类型：AI 报告、本地数据报告；缓存展示原生成时间、原快照身份，不能伪装成新检索报告。
- 正文可读渲染，保留证据链接、观测时间、数据缺口和结论限制；内容按安全渲染处理，不能直接注入模型 HTML。
- 报告读取失败、缺失、空正文、schema 异常分别展示；任何未知状态都不能改成“生成成功”。
- API 设置复用现有后端凭证存储。第三方节点为 `https://api.apikey.fan`，兼容路径/协议依当前后端配置；不因示例选择自动覆盖用户设置。
- 连接、模型、结构化、检索能力分别标已验证/失败/未验证；设置页加载不能自动测试模型或查询外部模型列表。
- 不展示 token 预算输入，不将 Key 放进 URL、前端包、预览或日志。

## 8. 顺序与逐段验收

### 第一步：统一外壳与真实扫描表格

完成导航、筛选侧栏、专业表格、抽屉和托盘；接真实快照。验证市值边界、AND/OR 三态、独立计数、未知排序、全部列、跨页选择、同币不同市场。七个旧模块保持可访问。此步不以 AI 成功为前提。

### 第二步：对象与投研链路

完成已选/指定对象、深度与提示词、预览确认、任务跟踪、扫描并投研。用离线 fixture 先验证身份、失败不回退、partial、缓存、重复提交与取消；后续由用户点测真实扫描与 AI。不得将离线模板报告作为真实 AI 验收证据。

### 第三步：报告阅读与设置

接真实历史列表/详情，验证报告类型、正文、证据/快照/缓存时间、错误状态与导出。设置保留凭证逻辑和分项能力状态，清除预算输入。

### 第四步：正式页面联调与交付记录

验证 320/390/768/1024/1440/1920px 布局，固定列、分页、托盘和侧栏滚动；键盘可操作筛选/表格/弹窗，弹窗管理焦点并支持 Escape，刷新恢复非敏感偏好。

检查正式 HTML 引用脚本全部可加载且无 404、控制台错误、重复绑定。页面载入无付费/外部调用；用户点击后才调用对应接口。核对运行服务实际加载的新页面与源码版本，无法证明时标“现网加载未验证”。

每步在 `DOCS/design/requirements.md` 文末追加：改动文件、行为、验证方法/结果、剩余缺口。用户已选方案和正式实施文档可由 GROK 归档到 DOCS 并更新 INDEX。完成状态至少区分“部分实现 / 代码已落地 / 离线通过 / 现网验收”，不能仅凭按钮存在就关闭需求。
