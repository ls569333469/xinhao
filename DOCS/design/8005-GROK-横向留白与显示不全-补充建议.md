# 给 GROK：横向留白收窄与显示不全的补充建议

用户最新要求：两侧留白适当缩减，页面显示更完整；保留舒适字号和纵向区块间距。

## 先处理两个确认阻塞

1. P1：pro-table-runtime.js:467的 style.textContent 模板字符串缺少结束符，解析在497失败；本轮node --check失败，8768静态返回同hash错误文件。先恢复脚本可解析，专业表/工具条/列宽调整才能运行。
2. P2：prototype.html主区域为裸 `<main>`，而a-shell.css一直写 `.content`。基础main有 max-width:1700px 与 margin:auto，宽屏仍居中留出较大空白；新增.content规则也不会生效。应让选择器实际命中主区域，并检查计算样式。

## 横向调整目标

- 扫描主区域取消1700px居中上限，充分使用导航右侧的剩余宽度。可给真实main增加一致类名，或直接对正确的main结构写规则；不要将选择器限定为当前并不存在的.content。
- 大桌面左右内边距16–20px，窄屏12–16px；不再建议宽屏40px横向留白。上下仍保留24–26px，区块纵向间隔20–24px，卡片内边距16–20px。
- 左侧筛选栏控制在260–280px，左右工作区间隙18–20px；1024px及以下筛选改到上方或折叠。主导航保留A布局，并确保可见，不能为拓宽表格隐藏七项入口。
- 表格列数超过可见宽度时，保留合理列宽并仅在表格区域横向滚动；不能缩回11px字号或强制数字断行。让右侧⑤⑥和行情列可以实际滚动查看，不只是隐藏溢出。
- 取消主区域上限后，检查整页没有横向滚动/裁剪；表格内部横向滚动不应被父级clip阻断。底部托盘不遮住横向滚动条。
- 保留全部26数据列与已有列偏好，不能删列让截图“看起来显示全”。纵向留白与横向使用空间分别调整。
