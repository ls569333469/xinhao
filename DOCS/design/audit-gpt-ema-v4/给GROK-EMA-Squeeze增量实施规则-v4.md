## 一页摘要

1. 先蓄力入候选池，再等待后续金叉；突破三线不删除。30天从该次入池时刻起算。
2. 完全金叉只认：当前闭合4H `EMA7>EMA25>EMA99`，且上一根 `EMA25<=EMA99`。不再用“上一根不是完整排列”代替。
3. 金叉当根或紧接下一根量能达到前7根均量2倍才确认；下一根仍不足则该事件作废，不等第三根。
4. 初始止损线为金叉根EMA99。只在4H收盘价严格低于止损线时发出退出信号；盘中触价不退出。
5. 首次有入场后的4H收盘价严格高于实际买入价，才开始按每根收盘EMA99上移止损；只能升、不能降。
6. 过去10根闭合4H中，至少3次收盘价创该窗口内此前最低收盘价，拒绝入池或移出未入场候选。
7. OI基准为该次入池保存的美元OI；当前美元OI严格低于基准70%时移出未入场候选。
8. RSI14在30–55、过去20根闭合4H最高high/最低low<1.35作为默认横盘条件。1.5及其他阈值只作后续研究备选，不自动启用。

## 3. 金叉事件与信号级别

对闭合K线t：

```text
full_cross(t) =
  EMA7(t) > EMA25(t) > EMA99(t)
  AND EMA25(t-1) <= EMA99(t-1)
```

这是用户修正后的强信号cross事件。上一根相等允许；当前相等不算。EMA25早已高于EMA99，仅EMA7从下重新穿过EMA25时，不是新的完全金叉；已有完整排列也不是新事件。

中信号保持：EMA7上一根<=EMA25、当前>EMA25，且收盘>EMA99，结合量能确认。弱信号为价上EMA99而EMA7<EMA25，仅提示，不放行入场。相同事件同一确认时点强级优先。此处“强／中／弱”是规则名称，不是经过验证的收益评级。

保存cross_time、cross级别、cross根EMA99、确认时间、实际可用时间、确认量比及事件ID。按市场+合约+规则版本+cross_time去重，避免反复扫描重复提醒或重复建仓。

## 4. 成交量只等一根

```text
vol_ratio(t) = V(t) / mean(V(t-7), ..., V(t-1))
```

分母不含本根。量比>=2是放量；分母<=0或缺失为unknown，不用0补齐。

- cross当根够量：该根收盘且数据实际可用后确认。
- 当根不足量：保留一次pending事件，只等紧接的下一根t+1。
- t+1够量：在t+1收盘后确认。此时量比的分母为t+1之前的7根，不能复用cross根的旧分母。
- t+1仍不足量：该次cross失效，t+2放量也不能兑现它；等待新的cross。
- 下一根数据缺失不把第三根当成“紧接下一根”。可从后续取得的历史数据补记事件事实，但不倒填实盘/模拟成交。

实施时保留原事件，不要求下一根再次上穿。等待期间结构已失效不得继续按原cross放行；强级检查完整排列仍成立，中级检查对应EMA7/25及价上EMA99状态。该项是避免陈旧事件兑现的执行约定，应一并进入新冻结定义。

确认与可成交时刻分开。离线回测可按确认后的下一根开盘作参考成交，计入原引擎规定的成本；实际扫描晚于该开盘时，不能仍声称成交在过去的开盘价。

## 5. 止损完整设计

### 5.1 初始线与追踪开关

初始止损线 `S = EMA99(cross_bar)`。若等下一根放量后才入场，也仍用保存的cross根EMA99，不偷换成确认根或入场根EMA99。

实际成交后开始观察盈利条件；入场以前已经收盘的确认根不能当成“入场后首次盈利根”。未发生入场后的 `close > actual_entry_price` 前，S保持固定。

首次满足后将trailing_activated持久化为true；以后价格回落也不重置。每根闭合4H更新：

```text
S_next = max(S, EMA99(current_closed_bar))
```

EMA99下降或相等不下调。不强制把S设为买入价，不加入用户未要求的保本线或追踪上限。

### 5.2 触发、执行与顺序

退出触发严格为：**4H收盘价 < 当根有效的止损线**。相等不触发；盘中最低价跌破但收盘收回，不触发本规则。

每根收盘按以下顺序处理，防止止损新线回溯生效：

1. 先用该根开始前已生效的S检查 `close < S`。
2. 若成立，记录退出待执行，下一根开盘执行参考市价退出；不再用本根EMA更新取消退出信号。
3. 若未触发，检查本根是否首次收盘高于实际买入价。
4. 若追踪已开启，更新S_next=max(S, EMA99本根收盘值)，从下一根开始生效。

本规则是收盘止损，不把盘中触价直接转换为退出事件。未默认增加盘中硬止损；如以后研究混合模式，另立版本。

“下一根开盘价出场”在OHLC回测中是执行假设，必须记成本与滑点。运行任务只可按信号实际可用后的可取得价格执行模拟，不能回填已过去的开盘成交；本文件不授权真实交易。

用户示例：初始S=0.030，某根最低0.028、收盘0.031，不退出；后续某根收盘0.029，发出退出信号，在紧接下一根开盘执行参考退出。

追踪示例：实际买入0.032，初始S=0.030。收盘0.031时不追踪；首次收盘0.033、EMA99=0.0305时，下一根S=0.0305；之后EMA99=0.0308则上移，EMA99=0.0306则保持0.0308。

### 5.3 入场当根与成本

若在下一根开盘参考入场，只能使用该时刻以前已确认的信息；入场后的第一根收盘即参与止损判断，不跳过。更晚才入场且本根OHLC无法确定前后顺序时，执行引擎需按实际可用时间或已有保守规则处理，不能使用入场前发生的价格来开启追踪。

手续费、滑点、资金费等复用已验证的计价和记账组件。退出信号和执行时序必须走本版新模式，不能直接沿用旧触价止盈止损；发生收盘退出信号后的下一开盘跳空，应按实际下一可执行价格处理。本规则不把“止损未触发”当成合约强平不会发生的证明，也不把收盘价当最终成交价。

## 6. 持续新低：10根中至少3次

取最新10根连续、闭合4H收盘价c[0..9]。第一根只作基准，不计新低。对i=1..9：

```text
new_low(i) = c[i] < min(c[0], ..., c[i-1])
new_low_count = sum(new_low(i))
deathTrend = new_low_count >= 3
```

严格小于才计数；重复同一最低价不计。不与窗口外的历史最低价比较；窗口每次滚动后重新从第一根作基准。未满10根、断档或数据无效为unknown。

用户例子的纠正：

```text
0.030, 0.029, 0.028, 0.029, 0.027,
0.028, 0.026, 0.027, 0.025, 0.026
```

按从1开始编号，第2、3、5、7、9根均创窗口此前最低收盘，共5次，不是只列的4次。最终排除结论不变。

这条明确替代当前函数“7日、每6根分组、连续3次组低点下降”的实现，不得把两者静默叠加或仍以旧算法显示已对齐。

## 7. OI萎缩：固定入池基准

候选进入时保存有限且>0的 `entry_oi_usd`，同时保存来源时间、取得时间、市场、合约及单位。

每次4H扫描取得新OI后：

```text
oi_contraction = current_oi_usd < entry_oi_usd * 0.70
```

严格低于70%淘汰，恰好70%不淘汰。不以“上一轮OI”作基准、不每轮刷新entry_oi、不用峰值替换。

例：入池OI=2000万美元，阈值1400万；当前1350万出池，当前1400万不因该条件出池。

数据缺失、过期或身份/单位不一致为unknown，阻止新入场确认，不能伪造萎缩。重启从持久化基准恢复；重新入池建立新的周期及基准。美元OI萎缩包含价格因素，不能宣称已经独立分离减仓和价格变化。

该条件针对未入场候选；不自动扩展成持仓OI退出规则。
