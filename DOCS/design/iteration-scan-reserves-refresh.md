# 扫描辅助储备自动更新方案

## 目标与范围

每轮正式扫描检查 DefiLlama 币安公开钱包储备，在发布扫描快照前取得最新可用的完整 UTC 日余额，计算日变化、7日变化和连续减少天数。行情、页面筛选/排序/详情、数据报告及后端投研使用该轮快照中的同一份辅助证据，不再依赖旧 HTML 中的静态样本。

储备变化是公开钱包余额变化，不能充当带标签逐笔净流入；不修改六指标⑤、命中数或策略执行规则。已核验来源映射仅限现有原生链资产，不承诺585份合约都有储备数据。

Santiment 的10资产70日历史样本保留独立来源和9月5—11日区间。本次不重复拉取旧历史、不调用AI、不使用权限受限的近期接口；当前精确净流仍为未完成的数据源依赖。

## 采集与缓存

1. 扫描完成行情核验后、发布前调用辅助采集。一次来源请求服务所有合约，按资产去重，不逐合约请求。
2. 只接受 Binance CEX 来源身份、原生链显式映射及连续8个完整UTC日余额；未来、重复日、缺日、异常数量拒绝补零。最近完整日边界不是部分日数据。
3. 当天最新完整日已齐且映射范围未变时复用缓存；缺口/滞后/失败后最多每小时请求一次，跨UTC日立即重新检查。网络有超时和体积限制，不无限重试。
4. 缓存保留原始采集时间，每次扫描重新计算36小时有效期及当前合约覆盖。更新失败可保留上次成功证据，清楚记录本轮失败、最后成功时间；过期转未知，不参加当前辅助筛选/排序。
5. 缓存只是采集优化；每轮不可变扫描revision保存证据全文和状态。失败扫描不能改变已发布页面证据。旧revision不回写。

## 发布与使用

- 扫描快照增加 `reserveEvidence`：来源、独立数据时间、采集/检查/尝试时间、状态、更新错误、失败资产、记录及覆盖。
- 页面HTTP加载将储备内嵌数据替换为同一次读取的扫描快照证据；读取新快照后同步重建辅助索引、表格、覆盖和详情。新版扫描缺证据时显示未提供，不能回退静态旧样本；旧版扫描可展示明确标记的历史样本。
- 后端投研从冻结扫描快照构建每个合约的储备证据，加入证据hash与模型输入。显示数据自身截止时间、采集时间、更新状态、有效性与“非精确净流”。不能把旧储备称为当前资金流。
- 采集失败不让行情扫描整体失败，但辅助状态必须可查；来源文件不可写也不得伪装缓存成功。

## 验收

针对性离线验证：新完整日刷新、当天缓存复用、跨日、异常来源、缺日/重复日/未来时点、限流/超时、失败保留、36h过期、不同合约集合覆盖、失败扫描不发布、旧revision不变、页面首次加载与扫描后刷新一致、投研证据/hash一致。请求桩禁止外网，AI调用为零。

上线前记录源码hash，检查在途任务再更新服务；用一次公共储备接口请求验收来源，不额外启动全市场扫描。真实全市场扫描联动在用户下一次扫描后确认；各阶段分别记录“代码落地/离线通过/来源实测/现网扫描联动”，不得混写。
