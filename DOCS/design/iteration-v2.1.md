# 异动观察 V2.1：交互整理、选币投研、提示词与多策略

本方案补充并优先于 iteration-v2.md 的对应页面设计。交付为可点击原型与实现规范；后台AI、调度、模拟账本未接入。原型改在原地址 http://127.0.0.1:8768/prototype.html ，正式面板8767未改。V2原型保存为 prototype-v2.0.html。

## 1. 系统化整理控件

现有问题：全局操作、筛选、排序、报告按钮散落在多层卡片；用户不易识别哪些改变查询、哪些发起任务。

统一组件约定：

| 层级 | 放什么 | 不重复放什么 |
|---|---|---|
| 全局顶部 | 数据时间、后台/AI状态、连接与设置 | 不重复各页任务按钮 |
| 左侧工作区导航 | 七个主要工作区 | 不混筛选条件 |
| 页面子导航 | 指标库/策略、任务/覆盖等视图 | 不混任务配置 |
| 单一查询区 | 范围、规则、结果显示；显示已选和筛选摘要 | 排序不再散在结果表格右上角 |
| 查询区底部操作条 | 一个主操作，2—3个必要辅助；其余“更多操作” | 不在多张卡片重复主按钮 |
| 行级 | 勾选、查看证据、必要单币动作 | 不复制全市场动作 |
| 表格底部 | 分页、结果数 | 不再添加筛选和任务按钮 |

市场查询分三组：01范围（搜索、市场、市值、映射）；02规则（六独立指标、组合方式，仅选择N时显示N）；03显示（满足/待核验切换、排序字段、方向按钮）。查询体可折叠，显示与操作保留。主操作为“选中代币投研”；全选、清空、观察池为辅助；采集、建策略、CSV、保存筛选放入更多操作。

其余页按相同约定整理：投研用三步单一任务表单；篮子用一张运行配置表；API设置测试、模型获取和保存集中在配置区。策略六步编辑仍保留，每步仅呈现相关参数。

## 2. 选择投研对象

报告对象来源改为可见的分段按钮：市场已选 / 当前筛选 / 指定代币 / 观察池 / 全市场简报。

- **市场已选**：表格新增复选框、选本页、选全部筛选结果；以market+symbol为身份，可跨页、跨筛选保留。币池明确展示，用户修改筛选不自动改变已选币。
- **当前筛选**：明确满足的全部合约，沿用市场排序；待核验不自动加入。用户切换币池或扫描更新时在任务提交前重新确认，后台任务锁定当次快照与名单。
- **指定代币**：搜索扫描目录，并点击具体合约加入；支持空格、逗号、换行批量输入；精确合约匹配优先，随后精确资产匹配；按身份去重。
- **歧义**：BTC等资产可对应USDⓈ-M USDT/USDC及COIN-M，必须明确合约，不隐式选USDT。未扫描到的代码不加入；正式版可启动目录核验和补查任务，不能编造报告。
- **观察池**：从已选或详情加入；原型仅当前会话，正式版持久化，加入不等于入场。
- **全市场**：全量程序简报和少数候选深研分开；不逐币调用模型。每日复盘来自已存实验账本，不作为选币来源选项，放验证页复盘任务中。

提交前显示“币池N份 / 本次M份 / 未提交K份”、明确顺序及所有被排除原因。上限默认10，仅为初值。截断不能静默：用户可调上限、手动分批或正式版明确启用自动分批；每批保留排序、名单、报告关系和预算预留。原型仅本次预览，不声称已排队后续批次。

报告预览已由固定GTC示例改为读取实际选择的合约生成六项数据报告。未调用AI的模板报告明确标注；切换选择后重新生成。单币详情→报告自动带入对应合约，不再跳到固定GTC正文。

## 3. 三档分析需要提示词

三档不是一个名称开关，也不是简单增加输出长度。实际提示词组成：固定证据与来源规则＋深度任务模板＋用户关注点＋所选快照证据＋结构化输出schema。

提示词设计保存在 prompt-templates.json，原型提供展开查看、编辑当前深度模板、输入补充关注点、恢复默认、记录本次修订、请求预览。

| 深度 | 任务范围 | 检索策略 | 初始Token预算 |
|---|---|---|---|
| 快速摘要 | 异常事实、关键反证、缺口、下一步确认；候选优先级 | 默认不外部检索 | 输入6000、输出1200 |
| 标准投研 | 六指标、量价结构、吸筹假设、事件、确认/失效、最多2个策略建议 | 可选；实际有证据才引用 | 输入12000、输出3000 |
| 深度研究 | 连续窗口、多假设、箱体/ATH、现货/链上/事件、多情景及最多3个独立策略建议 | 建议检索与依赖补查；缺能力清楚降级 | 输入24000、输出6000 |

预算可调，输入预算在正式后台通过实际token计数控制；模型上限、费用/日预算进一步约束。不允许丢关键证据却不说明。候选数多时分批；每个批次使用相同模板版本，最后篮子总结单独保留来源关系。

固定规则不可被用户补充、网页内容或新闻覆盖：事实/假设/反证/未知分开、不编价或成绩、不声称内幕主体、不误读OI/账户比/费率/成交窗口。即便深度模式，也不能没有证据就宣布已核验链上吸筹或全历史ATH。

正式版需要 **JSON Schema校验＋证据ID引用校验＋输出清理**，不能只靠提示词。原型请求预览展示字段契约，尚未实现后端校验。每份AI报告保存模型、实际协议、提示词版本/hash、补充文本hash、数据集、检索状态和调用量；编辑为新版本，不覆盖旧报告。初版不要求用户自己写提示词，使用默认模板即可。

## 4. 多策略可以同时跑

建议先3个不同逻辑的策略，之后按资源与样本需要增加。**启用策略数量、同时持仓数、AI任务并发是三个不同设置**。

原型提供8个模板选项、并行上限（1—8，原型设计范围，不代表后端性能结论）、权重、拟定资金上限、固定优先级、校验和均分。初值选择T1拥挤突破、T3异常换手、T5日线箱体，400/300/300U。它们目前是未冻结模板；数据不足时不允许运行，页面不显示假成绩。

两种资金模式：

1. **共享篮子**：总资金1000U，策略预算权重合计100%。预算是策略可占用保证金的上限，不是下单名义金额，也不保证损失只在预算内。账户可用保证金、策略子预算、单笔计划风险、篮子总开放风险和总持仓数都必须满足，不能只看权重。
2. **独立策略对照**：每策略一个1000U虚拟账户，同币同信号可以分别模拟；只比较各自曲线和成绩，不相加为1000U共享收益。显示虚拟实验总资金口径，避免误认实际资金。

共享账户规则：整篮子最多3仓、单笔计划风险0.3%、总开放止损风险1%、最高2×为未验证初值；同币按启用前固定的策略优先级只取一仓，并记录其他策略的冲突拒绝原因。不事后按收益选择优先级。默认不跨策略借预算；未来若允许借用必须独立冻结规则版本。

规则计算和区间行情复用不调用AI，因此多策略模拟不会按策略数增加高频AI调用。额外AI调用主要来自新报告、生成不同草案和复盘。多个策略不能重复计同一笔篮子交易的盈亏。

正式API需要账户策略绑定实体：account_strategy_bindings(account_id,strategy_version,weight,priority,max_positions,status,enabled_at)。启用先原子校验预算与数据依赖；分配/版本修改产生新配置版本，新信号用新配置，已有仓位保留入场时规则。暂停新开仓与停止追踪必须区分。

## 5. APIKEY.FAN 第三方配置

用户指定入口 https://api.apikey.fan 。本轮无鉴权只读核查：

- 根地址HTTP200，页面标题APIKEY.FAN，列出全球访问地址 api.apikey.fan 以及专线地址 slb.apikey.fan。
- https://api.apikey.fan/v1/models 未带密钥返回HTTP401。表明需要鉴权，不证明可用模型或实际协议兼容性。
- 根页指向 https://apikey.fan ，此次访问主站说明页返回HTTP403；未取得可验证的完整公开协议文档。
- 未使用用户密钥，未调用收费模型，未验证Chat Completions、Responses、Anthropic、JSON Schema、工具或内置检索。

页面加入APIKEY.FAN预设：候选Base URL为 https://api.apikey.fan/v1 、候选协议为OpenAI兼容Chat Completions；两者明确待鉴权验证，可编辑，不标成已接入。请求预览防止重复拼接/v1，模型ID不臆填。

正式版接入顺序：

1. 用户在正式设置填Key，由本地后端保护存储；原型请勿填真实Key。
2. 后端向指定地址读取可用模型（若服务支持）；显示真实ID、可用状态和失败原因，不展示猜测模型。
3. 明确选择协议和模型，测试一次小请求（可能计费）；验证结构化输出，并在不支持时走解析＋校验，不声称原生Schema保证。
4. 独立验证工具/检索能力；没有内置检索时接独立检索适配器，不能把普通文本生成当作联网搜索。
5. 分别绑定投研、策略、复盘，日志记录实际网关与模型、限流/额度、Token和费用估算。第三方计费可能不同；没有价格时显示待核算并用调用/Token限制。

只将用户授权的研究内容和所选公开行情提交到用户配置的网关，凭证留在后端；不默认切换网关或备用服务。Base URL自定义可用，但需校验路径、重定向和密钥目的地址。专线地址未测试，不默认替换用户指定地址。
