## 1. 我们已经达成的方向

目标是把币安永续市场观察工具扩展成“扫描 → 投研报告 → 多策略制定 → 模拟验证 → 复盘”的完整工作台。初始模拟资金1000 USDT，先研究和模拟，不连接实盘下单。

- 扫描全部活跃 USDⓈ-M 与 COIN-M 永续合约；同资产多合约分别统计，另有资产汇总视图。
- 六个原始指标各自可选，支持 AND / OR / 至少 N 项，可叠加市值、成交额、市场和数据质量条件，支持排序与保存预设。
- 增加疑似吸筹持续性、日线箱体、接近/突破ATH及趋势、量能、合约结构等指标；指标库逐步扩充，每个策略仅引用必要指标。
- AI结合数据及可追溯的公开信息生成报告，报告可生成多个策略草案；结构化审核后冻结版本，再验证。
- 支持手动更新和定时更新，默认周期建议4小时。行情计算、记录、模拟撮合及绩效统计由程序完成，不高频调用AI。
- 从现在开始记录信号、策略、模拟成交和后续价格，积累前向验证样本；能取得的历史数据可补查，单独运行历史回测。
- AI API在页面配置，能查看连接状态、调用量、预算和失败原因。没有配置API时，数值扫描、规则筛选和模拟仍可工作。

## 2. 已有基础与真实缺口

核对现有 index.html、scanner.py、server.py、scan.json 和实测报告：

| 功能或数据 | 目前状态 | 本轮设计如何承接 |
|---|---|---|
| 全市场采集 | 公开REST接口采集，页面仅读取已有文件 | 新增真正启动采集的按钮和任务状态 |
| 筛选、排序、CSV、六规则说明 | 已实现 | 保留三态逻辑、排序与筛选习惯 |
| 报告 | 确定性证据模板；聊天中可AI复核 | 分开标记“数据报告 / AI投研报告” |
| 后台AI、任务调度、策略账本 | 未实现 | 新增独立配置、任务和持久化模块 |
| 当前存量 | 一次快照：588合约；市值518；EMA587 | 可筛选候选，不能当作连续历史 |
| 链上净流 | 0覆盖 | 显示未接入，禁止视为0或未命中 |
| 完整OHLCV、日线、ATH | 未归档 | 更新采集时同时保存；候选按需补查 |
| 连续OI/账户比/市值 | 尚未建立 | 每次更新归档，可用历史来源单独补齐 |
| 已做测试 | 16规则×2范围，32组筛选测试 | 标记为筛选校验，不展示成胜率 |

当前快照采样为北京时间2026-10-12 20:03:26—20:07:37。588是合约数，不是独立代币数；525个资产。页面图片的1000万（含）—5000万（不含）美元范围为177份合约，仍有70份缺市值可能属于此范围。涉及这些合约的结果应进入“待核验”。

早期示例中的“多空比越低越好”“三线下方就是底部”“负费率很快必涨”“量增价平就是吸筹”等不作为产品规则。账户比与持仓比分栏；费率年化按实际周期计算；OI是名义敞口，不是保证金或可强平金额。

## 3. 页面结构与统一交互

左侧导航七个工作区：**市场扫描 / 投研报告 / 指标与策略 / 模拟篮子 / 验证与复盘 / 数据与任务 / 设置**。顶部固定显示数据时间、扫描状态、AI状态，以及“立即扫描”与“生成投研”。

所有页面遵循：

1. 页面显示所用快照、策略版本和数据可得时间，不把旧数据包装成实时行情。
2. 满足 / 不满足 / 未知三态并列。覆盖缺口与质量问题可点击定位；“未知”不折算成0。
3. 扫描、投研、回测为异步任务，可离开页面，返回后查看结果；不能凭动画宣称任务成功。
4. 重大参数保存前展示变更摘要；扫描筛选可以直接调整，已启用策略规则变更必须创建新版本。
5. 空态给出下一步：未配置AI、数据不足、没有触发、尚无已平仓样本、任务失败各自有不同文案。
6. 桌面用表格＋右侧详情，窄屏折叠导航并保留关键列；表格可横向滚动，操作可键盘使用。
7. 原型使用既有历史样本和清晰标记的演示状态；点击不会采集、调用模型、保存密钥或开启任务。

### A. 市场扫描

上部：采样窗口、目录覆盖、明确命中、待核验、候选变化。按钮明确区分“立即扫描全市场”和“重新读取已存快照”；扫描完成后保持原筛选。

筛选区：市场（全市场 / USDT / USDC / COIN-M）、资产或合约视图、市值预设与上下限、成交额下限、映射可信度、数据新鲜度、名称搜索。保留六卡片独立命中数，再用“添加指标”抽屉选择扩展项；保存命名筛选预设。

组合区：AND / OR / 至少N项；支持“行情结构组 AND 合约证据组”分组。未知处理默认待核验，只在明确展示放宽依赖的规则副本中允许跳过，不能静默降级原策略。

表格：合约、价格、市值、命中/已知数、六证据、形态状态、数据质量、候选增减。排序支持全部现有字段，扩展箱体距离、ATH距离、ATR和流动性；缺失值始终排最后。

详情：分“行情结构 / 合约结构 / 链上 / 事件 / 来源”。每字段可看时间、公式、来源；按钮为“加入观察池”“生成单币报告”“用当前筛选建策略”，加入观察池不等于开仓。

### B. 投研报告

左侧为报告列表：全市场简报、当前筛选篮子、单币深研、每日模拟复盘。筛选报告类型、时间、模型、快照及策略关联。

报告配置：范围、分析深度、候选上限、是否公开检索、新信号优先、缓存策略、预算预估。建议默认每次详细分析前10个变化候选；这是可编辑起始配置。

正文固定分区：

1. 数据时间、币池、证据覆盖和结论摘要。
2. 六项证据：原始数值、阈值、命中状态及来源。
3. 行情结构：趋势、箱体、ATH口径、潜在突破和失效。
4. 吸筹假设：支持证据、反证、独立时间窗口及不确定性。
5. 事件与基本面：公告、解锁、供应及现货/链上证据，附链接与发布日期、检索时间。
6. 条件化方案：等待什么确认、失效条件、是否适合某策略，而非命中直接买入。
7. 策略建议：推荐模板、参数草案、依赖缺口及适用验证模式。

底部“生成多个策略草案”保留报告ID、引用证据ID和数据版本；AI草案进入校验，不能自动启用。下载Markdown / JSON；CSV导出证据表。模型失败时可生成数据模板报告，但不得标成AI成功。

### C. 指标与策略

两个子页：指标库、策略工作台。

指标库每项展示名称、类别、公式、周期、阈值、单位、当前覆盖、历史覆盖、依赖、版本和状态（可用 / 待补数据 / 未接入）。支持收藏与自定义阈值。筛选阈值和已冻结策略阈值分开。

策略列表按“草稿 / 待补数据 / 可验证 / 模拟运行 / 暂停 / 已归档”筛选；每卡展示版本、来源报告、触发规则、依赖覆盖和样本数。提供从模板、报告、当前筛选或自然语言创建的入口。

策略编辑分六步：

1. 名称、方向、币池、合约类型、周期和来源报告。
2. 候选条件、数据新鲜度、候选有效期和排除条件。
3. 入场触发、执行时机、收盘确认或预设触价、是否等待回踩。
4. 初始止损、止盈、分批、移动止损、时间退出、失效退出。
5. 仓位风险、保证金、并发限制、同币冲突、手续费和滑点。
6. 规则摘要、依赖预检、与上版差异、保存新版本、冻结并选择验证模式。

AI输出必须是白名单JSON规则，不执行AI返回的代码。若报告没有可靠支撑压力、箱体或ATH，相关字段显示缺失，不能捏造价格。

### D. 模拟篮子

分“篮子账户”和“独立策略对照”。默认1000 USDT模拟账户；对照策略各自资金曲线独立，不合并成一个篮子的收益。

账户卡：权益、可用资金、占用保证金、已实现/未实现盈亏、开放止损风险、成本、当前持仓。收益均基于模拟账本，未开始时不填演示收益。

列表：候选观察、待入场、持仓、已退出、拒单/失效。列出信号与实际模拟成交的不同时间、价格、策略版本、止损/止盈、规模、费用、资金费率、最后追踪时间与数据缺口。

每次跟踪保存区间行情和资金结算记录，不调用AI。点击一笔可看到事件时间线与关联报告。支持暂停新开仓、继续追踪原仓、按规则下一可用价格模拟平仓；暂停/重启语义需明确。

同币多策略：独立对照可分别持仓；篮子按固定优先级只保留一个方向的一份仓位，不叠加冲突资金。名额不足按事先固定排序处理，不能看事后收益选币。

### E. 验证与复盘

三个明确分开的模式：

| 模式 | 用途 | 页面要求 |
|---|---|---|
| 历史回测 | 用已取得、时间一致的历史数据测试冻结规则 | 起止区间、预热、历史币池、市值口径、覆盖预检 |
| 前向模拟 | 从启用时开始记录新信号和模拟交易 | 起始时间、规则版本、跟踪完成度、延迟、样本数 |
| 记录回放 | 对既有快照与账本复现原判断 | 数据集版本、来源、是否改变规则；修改规则另算新实验 |

结果：资金曲线、基准、净收益、最大回撤、已平仓胜率、平均盈亏、盈亏比、期望值、持仓时长、手续费/资金费率/滑点、有效及排除样本。无样本显示“暂无”，不显示0%胜率；未平仓不纳入已平仓胜率。样本少明确显示数量，不输出“已证明有效”。

多策略比较必须用相同币池、区间、成本、数据质量和资金口径。参数探索和最终测试区间分开；每次实验保存参数，策略改动重新开实验，不能覆盖旧成绩。

历史不足时显示“可做前向验证”，而不是禁止一切验证；某指标历史缺失则阻止宣称该完整策略已做历史回测。

### F. 数据与任务

子页：任务记录、扫描历史、数据覆盖、调用成本。

任务状态：排队 / 运行 / 成功 / 部分成功 / 失败 / 取消。显示任务类型、阶段、已处理/总数、时间、错误摘要、重试、关联输出。扫描同一时刻只运行一份；手动与定时重合时复用在途任务。

覆盖矩阵按指标×合约显示当前和历史覆盖。查看缺市值、低可信映射、K线断档、链上缺口、历史源保留期限。支持针对候选补数据，保存原始响应摘要和标准化记录。

历史快照不可覆盖；最新成功快照原子发布，失败保留上次成功数据。删除普通缓存与删除验证账本分别处理，不自动清理未结实验依赖数据。

### G. 设置

设置分六个子页，保存后显示“待应用 / 已生效 / 需重启”的真实状态：

| 设置页 | 字段与操作 | 起始建议 |
|---|---|---|
| 更新与调度 | 自动扫描开关、间隔/执行时点、时区、恢复补跑、区间K线补查、每日复盘时刻 | 默认关闭；启用后4小时；显示时区 |
| AI API | 接口协议、服务商预设、Base URL、API Key、模型ID、任务绑定、超时、重试、测试连接 | 未配置；模型ID由用户填或兼容接口加载 |
| 检索与数据源 | 公开检索服务、密钥、域名优先、数据源/链上供应商、映射及缓存 | 已有公开行情；链上未接入 |
| AI预算与缓存 | 每次候选上限、输入/输出限制、并发、日调用/Token/费用上限、复用周期、触发变化 | 只分析变化候选；预算耗尽暂停AI而非扫描 |
| 模拟与成本 | 本金、杠杆、并发、单笔/篮子风险、每边费率、滑点、区间歧义规则 | 1000U、最高2×、最多3仓、0.3%/1%计划风险 |
| 存储与展示 | 时区、主题、数据目录、备份、导出、保留期限、健康状态 | UTC存储，页面可选北京时间；实验依赖不自动删除 |

本金1000U为用户已给条件；其余是未验证的可编辑建议。单笔3U和篮子10U为计划止损风险，不是保证实际最大损失。费用字段必须明确单边与单位；默认0.05%单边费率、0.05%单边滑点仅作模拟初值，不代表用户真实账户等级或市场实际成交。

#### AI API填写设计

- 协议单独选：OpenAI Responses / OpenAI兼容Chat Completions / Anthropic Messages。预设只填写适配协议与常见端点，不能假定任意兼容服务支持工具调用、JSON Schema或检索。
- Base URL、API Key（密码框）、模型ID为基础。代理网关使用自定义URL，不能将密钥默认转发到其他服务；后端校验目标、协议、重定向并禁止访问无授权的本地元数据端点。
- “测试连接”发起明确提示的一次小模型请求，可能计费；分别显示鉴权、模型可调用、结构化输出、工具/检索支持。保存配置和连接测试分离，测试失败不覆盖上次有效配置。
- 同一配置可绑定投研、策略草拟、复盘；后续允许多个模型配置。备用模型必须用户明确配置，页面展示实际使用者。
- 未填写Key→未配置；已保存→待测试；测试通过→可用；鉴权失败/限流/余额不足/协议不支持分别显示，不笼统提示“AI失败”。
- Key只提交到本地后端，保存于Windows保护的凭证存储/DPAPI加密文件，目录不得由静态路由提供；页面只返回配置ID和是否已配置，不能回显明文。禁止localStorage、导出、日志、URL带Key。不自动读取其他项目凭证。
- “保留现有密钥”“替换”“清除”显式区分；空输入不等于删除。测试/保存/清除均需同源写接口及本地访问保护。
- 检索是独立能力：没有检索提供商或模型支持时明确显示“未启用外部检索”，可继续数据解读，不能输出虚构来源。
- 调用记录保留任务、模型、Token、耗时、缓存命中及费用估算；未知价格显示“费用待核算”，不伪造精确金额。

## 4. 指标扩展路线与定义

| 类别 | 指标 | 数据与口径 | 阶段 |
|---|---|---|---|
| 原六项 | 单合约OI/市值、账户多空比、当前费率年化、三EMA压制、交易所净流出、量增价平 | 保留现有公式和三态；⑤依赖可靠链上标签 | 基础；⑤后接 |
| 量价趋势 | EMA排列/上穿、量倍数、本根量异常、ATR、RSI、MACD、ADX、收益/波动、回撤 | 保存完整OHLCV；周期、预热及算法版本固定 | P1 |
| 买卖主动性 | Taker买入占比、现货/合约量比、OBV、CMF、VWAP | 已收盘成交字段；现货配对需资产映射；OBV/CMF不等于真实净流入 | P1–P2 |
| 合约变化 | OI变化、价/OI联合状态、费率持续性、账户比变化、基差 | 独立时间序列，实际结算与当前显示值区分 | P2 |
| 日线箱体 | 箱体上下沿、宽度、驻留天数、触碰次数、突破幅度、回踩状态 | 只用触发日前已收盘日线构造，不含突破当根 | P2 |
| ATH | 上市以来最高价、全市场ATH、距高点%、突破/回踩 | 清楚区分来源、完整度、乘数、迁移、历史区间 | P2 |
| 疑似吸筹 | 收窄波动、重复量价平、主动买入、现货确认、交易所净流、抛压与低点结构 | 使用独立窗口和反证；非证明主力/内幕持仓 | P2–P3 |
| 质量与事件 | 成交额、点差、深度、新上市、解锁、公告、供应变化 | 深度快照不可冒充历史流动性；事件保留发布日期和首次可得时刻 | P2–P3 |

指标目录覆盖上述类别，可扩展到30项以上，但不以数量替代验证。P1先支持最可靠的数据项；每项都必须有公式、依赖、未知条件和测试。

**日线箱体初始定义建议**：前20/30/60个已收盘日，排除触发日；上沿max(high)、下沿min(low)，宽度=(上沿−下沿)/中轴；限制收盘驻留和边界触碰次数。参数可选，盒子生成规则版本固定。突破采用日收盘超过上沿及固定缓冲，回踩是后续状态，不能用事后箱体调整触发。

**ATH定义**：同合约触发前历史最高high为“上市以来高点”；全市场ATH需独立可信全历史源。历史不足只能称区间高点。今天查到的ATH不能直接回填过去，历史回测每一步只用此前高点。

**吸筹持续性**：连续4小时取重叠24h量价窗口会重复观察同一批成交，不能计作多个独立证据。使用独立4h/日窗口，至少多个窗口＋主动成交/现货佐证；量增下跌、OI骤降、持续低点下移等作为反证。没有链上标签时显示“量价吸筹假设”，不能称链上吸筹或老鼠仓确认。

## 5. 首批策略模板

所有参数均为待验证草案，每个模板都可以保存多个版本。当前快照只够筛候选，具体价格由新增行情依赖计算后填入。

| 模板 | 候选条件 | 后续入场触发 | 主要退出/依赖 |
|---|---|---|---|
| T1 空头拥挤突破 | ①②，③加分或设为必选；设置追涨排除 | 已收盘4h突破EMA99＋量确认，或随后回踩守住 | 局部低点/ATR止损、R倍数止盈、时间退出 |
| T2 跌势修复 | ①②④候选，不立刻开多 | 收复均线并回踩；候选限时有效 | 修复失效退出；候选状态与触发分时 |
| T3 异常换手突破 | ⑥，现货/主动买入作为额外证据 | 突破预先定义区间＋量确认 | 放量下跌排除、结构止损 |
| T4 疑似吸筹后突破 | 多个独立窗口量价/波动及买盘证据 | 箱体上沿确认或回踩 | 缺独立窗口仅待补数据，不称持续吸筹 |
| T5 日线箱体突破 | 已形成合格日线箱体，可叠①②③⑤⑥ | 日收盘突破固定上沿，下一可执行价或后续回踩 | 重回箱体、结构止损、时间退出 |
| T6 接近ATH观察 | 距历史高点小于可调阈值、趋势/量能条件 | 真正突破前只观察 | 触发前ATH固定；上市高点/全市场分别标识 |
| T7 ATH突破/回踩 | 完整对应口径ATH，放量/合约证据可选 | 收盘突破或后续回踩 | 回落失效、ATR移动止损；无上方历史压力不编价 |
| T8 趋势延续 | EMA多头排列、ADX/量/流动性门槛 | 回踩均线后收盘恢复或前高突破 | 趋势破坏、移动止损、到期退出 |

共用风险排除库：放量下跌、价跌OI增、过度追涨、重大解锁、点差/深度不足、低可信市值、陈旧数据。风险排除本身必须有证据，未取得时按策略的未知处理。

不要同一时刻既要求“三线下方”又要求“突破EMA99”。用候选→等待→触发→持仓→退出/失效状态串联；候选有效期建议初值24h，允许调整。OI、费率、买盘等证据必须指定在候选时冻结还是入场前复核。

## 6. 四小时更新、AI成本与模拟账本

推荐首版流程：

1. 到点或手动启动 → 拉取目录、行情、指标；持仓/已启用规则先补齐上轮至今的小周期K线和资金结算。
2. 归档原始数据与标准化快照；根据旧版本已激活的规则推进模拟状态，记录事件发生时间与本轮发现时间。
3. 当前扫描完成 → 判定新候选及变化；低成本生成全量数据简报。
4. 只对新增或变化达到阈值的候选调用AI；重复候选复用有期限的报告，页面显示原报告时间与新证据。
5. 新报告生成策略草稿，用户冻结/启用后才开始新模拟；每日复盘可调用AI一次，统计本身不调用AI。

每天4小时一次为6次扫描，并不等于每币6次AI调用。费用随候选量、上下文、模型和检索而变，无法预先承诺固定费用。每日预算上限、候选数和变化阈值在设置里控制；达到上限只暂停新AI分析。

**不要求每1–5分钟调用AI，也不要求首版高频轮询。** 每4小时补查1m/5m等可得区间K线，以固定规则检查止盈止损。结果最多延迟一个更新周期；它是延迟发现的模拟事件，不是实时实际成交。

若上轮已经激活固定价格触发规则，可在本轮补数据时回放期间触发，记录 event_at 与 observed_at。若策略在本轮报告后才生成，不能回填本轮之前的盈利入场。收盘信号默认下一可执行价格成交；预设价格单还需撮合/跳空假设，不把K线触碰自动等同实际订单成交。

保存事件账本：候选/信号/规则启用/模拟成交/持仓更新/费用/资金结算/部分退出/止损止盈/失效/拒单/数据缺口。事件追加写，不覆盖旧记录。

最少字段：event_id、account_id、experiment_id、strategy_id/version、report_id、snapshot_id、market/symbol、event_type、event_at、observed_at、available_at、trigger_rule、原始与模拟价格、数量/合约乘数、保证金、止损止盈、手续费/滑点、资金费率现金流、权益、退出原因、数据质量、规则和数据hash。

同根同时触及止损止盈：细化K线；仍无法确定默认止损优先，标记歧义样本。数据中断保留未结状态，补齐后再结算，不以最后报价假装止损成功。费用按每边收取、资金费率按持仓方向/结算时刻/名义金额计；COIN-M需独立反向盈亏与抵押资产估值引擎。

初版篮子引擎先支持USDT线性永续；USDC/COIN-M可扫描但不可静默套用USDT模拟器。模拟结果未包括完整清算路径时，页面展示清算模型未实现，不声称可复制实盘收益。

## 7. 工程模块与持久化

设计中的后台模块：数据采集与归档、指标注册表、任务/调度、AI适配与检索、报告、策略校验/版本、事件驱动模拟、回测与统计、配置与凭证。

推荐SQLite元数据及账本＋按时间分区的OHLCV/快照文件；数据库事务和原子快照，任务单实例锁、去重键、断点与重启恢复。明确服务需运行、联网且设备不休眠；恢复后补一次缺口，不重复跑所有错过调度。

核心实体：scans、observations、candles、indicator_versions、reports、strategies、strategy_versions、experiments、accounts、events、positions、funding_cashflows、tasks、schedules、model_profiles、usage_records、source_metadata。字段级时间、时区、交易单位与来源统一。
