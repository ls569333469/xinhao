# 更新、策略制定与回测实施方案

> 本文件为前期方案，保留历史讨论。最新需求与实施顺序以 [统一需求文档](design/requirements.md) 为准；检查结果见 [整体设计与代码检查](design/design-code-review.md)。早期描述中的Token预算输入、T1/T3候选及部分数据状态已被新版修订。交互原型为 `design/prototype.html`，后台闭环仍未接入。

状态：方案评估；本文件不表示功能已上线或定时任务已开启。

## 已确认的基础

现有scanner.py通过公开REST接口扫描活跃USDⓈ-M与COIN-M永续，用程序计算六项规则。页面读取scan.json；“读取最新扫描文件”不会发起新采集。server.py目前只提供GET静态文件和扫描结果，没有任务启动、调度、策略或回测接口。页面报告是证据模板；AI复核由当前聊天完成，没有独立后台模型服务。

现有数据是一次完整快照及逐合约观测，尚未建立连续完整的历史指标库。⑤链上交易所净流出未接入。300根4hK线主要用于当前EMA初始化，不等同可用的多年回测集；候选只补了最近4次资金费率结算。

## 产品结构

1. 市场面板：沿用六指标筛选，新增“立即扫描全市场”、任务进度、上次成功时间、错误摘要、定时设置。保留“重新读取快照”并注明其不重新采集。
2. 策略工作台：使用自然语言或当前筛选生成策略草案，展示结构化规则、缺失指标与可回测范围；保存版本后用于回测。配置币池、市值/指标组合、周期、入场确认、退出、仓位、同时持仓、成本、观察期。
3. 回测页：选择冻结策略版本、币池、时间段、历史数据模式，先检查覆盖率，再运行；输出资金曲线、成交、收益/回撤、胜率、盈亏比、费用和资金费率、排除项及数据限制。
4. 历史与报告：每次采集保存可追溯完整快照，生成指标独立与组合命中、新增/消失、风险和数据覆盖报告；AI报告单独显示模型、时间、来源、使用的策略版本。

## 更新任务

- 网页通过同源POST创建后台任务，快速返回任务ID；后台执行公开接口采集，页面轮询状态。一次只允许一个扫描任务，重复手动/定时触发复用在途任务。
- 推荐定时间隔4小时，默认关闭，由设置启用；支持1/4/8/24小时。时间明确显示北京时间和下次触发。调度设置持久化。
- 调度器位于本地服务进程；服务需运行、设备需联网且未休眠。重启/恢复后只补一次过期任务，不堆积多个扫描。
- 限流按源退避，市值合理缓存且保留源时间；单项错误保留未知。目录读取失败不得发布空扫描覆盖成功快照。
- 原子发布新的scan.json，同时保存完整历史；失败保留上次成功结果，标记本次失败/覆盖下降。历史记录分别保存采样窗口及每项可得时间，不能把跨4分钟扫描看作同一瞬间。
- 浏览器面板保持当前筛选；更新完成后重新评估当前规则，不改变保存策略阈值。

## AI角色

数据接口提供可核实观测，程序承担可重复计算及交易模拟，AI负责任务编排、规则草拟、公开事件检索、证据解读与报告。全量采集不需要每个合约调用一次大模型；全市场数值扫描后对候选和异常做AI分析。

后台AI功能需单独配置可调用的模型API/受支持服务以及事件检索工具。当前聊天能够分析市场，不等同本地HTTP服务具备持续自动AI调用能力。不得自动读取用户其他项目的凭证；配置未完成时明确显示未启用AI解读，数值更新仍可工作。

策略草案使用严格结构化字段与可执行运算符白名单；不执行模型返回的任意Python/JavaScript。规则校验并锁定版本后才运行回测。显示阈值、数据依赖、缺失处理、触发时间与成本假设，不把命中数当成概率。

## 回测分层

### A. 历史量价回测

先实现④EMA与⑥量价规则，回补区间K线及预热窗口。建议4h周期、近90天为初始默认，但应根据实际可得历史裁剪并展示覆盖；本金1000 USDT。当前市值过滤只能定义“按当前市值挑选的币池”，不得冒充历史市值条件。默认先测试线性USDⓈ-M USDT计价合约；COIN-M/USDC的收益、费率和保证金币种需分别实现，不混用线性USDT引擎。

明确标注当前上市币池的生存者偏差；没有退市历史时不称币安历史全市场。单合约新上市/缺历史不强行补值。

### B. 六项证据历史/前向验证

先验证OI、账户多空比、历史流通市值、已结算费率及链上净流的供应商覆盖、频率、可得时间和授权成本。缺历史的指标不能用今天的值回填过去，也不能去掉后仍声称完整六指标策略。

从开启采集时开始积累①②③④⑥完整观测；⑤在取得可靠交易所标签流并排除内部迁移后加入。模拟信号只能在整次扫描完成且相关数据已可得时触发，使用此后的可执行成交价。累计数据用于后续前向模拟，不宣称立即拥有长期历史。

## 回测执行口径

- 策略区分“候选筛选”与“入场触发”；价格低于EMA与突破EMA不可要求同一时刻同时成立，使用候选状态的有效期和后续突破确认。
- 信号只用当时已收盘且可得的信息，下一根开盘或实际后续可执行价格成交。不得同根收盘识别又以该收盘无摩擦成交。
- ①按当时OI/当时流通市值；③区分当时可见费率指标与未来实际结算现金流，按结算时刻和持仓名义价值计费。
- 费用每边分别计，滑点可调；止损跳空按可执行开盘/价格处理。一个4h柱内同时触发止盈和止损但缺更细数据时采取止损优先并统计歧义，不默认最佳顺序。
- 资金管理基于整篮子同时持仓，禁止把各币独立1000U回测收益直接相加当作1000U篮子收益。建议起始最多3个持仓、逐仓、最高2倍杠杆，单笔风险0.3%、篮子开放止损风险上限1%，另计费用及跳空；这些为可编辑模拟参数，不保证实盘亏损上限。
- 仓位风险预算与可用保证金同时约束。交易所精度、最小名义金额、费率、杠杆/维持保证金规则需要时间一致数据；缺乏完整清算模型时报告注明不能验证强平路径，不声称实盘收益可复现。
- 参数优化使用训练/验证区间，最终测试期独立且冻结；AI只在回测结果之后解释，不使用测试期选择阈值后报告无偏收益。

## 验收

手动更新确实启动新采集；定时与手动并发不重复；失败不覆盖成功快照；重启后定时配置恢复；六项覆盖变化可追踪；AI不可用有明确状态；相同策略版本和数据集回测可复现；缺失历史、未来数据和当前市值回填不能静默通过；资金与费用账可核对；报告对应策略版本及数据时间。

## 建议实施顺序

1. 手动更新、4小时可配置调度、完整历史归档和任务状态。
2. 结构化策略编辑/版本保存及④⑥量价历史回测，先用确定性规则验证数据和模拟引擎。
3. 配置自动AI草拟/报告；对①②③历史覆盖逐项接入，积累全规则前向验证。
4. 接入⑤可靠链上数据后扩展规则和回测覆盖。

当前范围是研究与模拟；不包含自动下单。
