## 1. 页面筛选 / 组合预设 / 策略模板 / 篮子 / 回测是否一致

### P1-1 三套策略定义并行（已确认 · 高）
- **位置**：`design/prototype.html` ≈L147 `combinationPresets`；≈L164 `recommendedStrategies`；≈L168 起 `templates[0..]`（及更早内嵌 templates）。
- **事实**：预设用 `indices`（如 squeeze=`[0,1,2]`），推荐用自然语言候选+触发，模板卡片再用另一套文案；T1–T3 语义大致对齐，但 **无共享 `strategy_id/version` 注册表**。
- **触发**：改一处指标阈值或文案时，另一处不同步。
- **影响**：市场筛选、模板卡、「查看推荐」可能描述不同规则；无法保证篮子/实验引用同一冻结版。
- **建议**：单一注册表驱动筛选勾选、模板卡、报告草案、预检；页面只渲染注册表。
- **验收**：改 I1 阈值一次，五处文案与候选计数全部自动变化；导出配置含同一 version hash。

### P1-2 T4–T8 「查看推荐」跳到前三篮子叙事（已确认 · 中）
- **位置**：`prototype.html` ≈L173 模板卡 `data-goto="basket"`（与 L11 抽取一致：templates map 统一挂 basket）。
- **影响**：用户点 T5/T6/T7 等仍落到 T1–T3 推荐区，易把「缺数据模板」当成可跑策略。
- **建议**：每模板独立指导页；缺数据标「无法判定」，禁止跳到可运行推荐。
- **验收**：点 T5 只看到「无日线/箱体，不可算」，不出现 T1 入场话术。

### P1-3 篮子与回测规则仅 UI 预览（已确认 · 高）
- **位置**：需求 §3.4–3.5；`server.py` 仅 GET；原型按钮多为 toast / data-demo（既有检查已列）。
- **影响**：1000U、40/30/30、止损 0.3% 等是表单预览，**无撮合、无账本、无回测引擎**。
- **建议**：在 R2 前页面持续标「流程预览」；不要用预览参数写收益结论。
- **验收**：任意「开始模拟/回测」无后端任务 ID，且状态非 success。

对照：与既有 C01/C06/C02 一致，非复述——以上行号来自本次对 `prototype.html` 抽取。

## 2. 六指标公式 / 单位 / 窗口 / 市值 / 未知值

### P2-1 采集侧公式与需求基线大体一致（已确认 · 信息）
- **位置**：`scanner.py` `classify` L175–181；量窗 L160–167；EMA L64–69、L150–158；费率 L128–131。
- **核对**：
  - I1：`oiUsd/capUsd*100 > 30`（名义 OI，非保证金）
  - I2：`accountRatio < 0.8`（全体账户比；大户比在 `refine` 另列）
  - I3：`fundingAprPct < -50`，年化=`pct*24/hours*365`
  - I4：已收盘 4h 低于 EMA7/25/99
  - I5：`None` 固定未知（L181 第 5 项）
  - I6：非重叠 8×6 根 4h 窗，`vol>3` 且 `|Δp|<2%`
- **验收**：`node verify-filters.cjs` 对当前快照命中 [68,42,15,289,0,3]（测试 L16）。

### P2-2 `number()` 接受非有限值（已确认 · 中）
- **位置**：`scanner.py` L58–62。
- **触发**：上游返回 `NaN`/`Infinity` 字符串可被 `float` 吃进。
- **影响**：OI/市值/费率可能写成非有限数，污染筛选与排序。
- **建议**：`math.isfinite` 门禁；写入前丢弃。
- **验收**：注入 `"nan"` 字段后该指标为 unknown，不进命中。

### P2-3 资金费率周期默认 8h（已确认 · 中）
- **位置**：`scanner.py` L127–128，`intervals.get(symbol,8)`；`fundingIntervalSource` 自承「标准 8h 默认」。
- **影响**：真实非 8h 合约年化偏差；需求要求周期未知标估计。
- **建议**：无 `fundingInfo` 时标 `estimated`，I3 三态降级。
- **验收**：缺 interval 的合约 I3 为 unknown 或带估计旗标。

### P2-4 同资产 OI 合计无覆盖完整度（已确认 · 中）
- **位置**：`scanner.py` L269–274。
- **影响**：部分合约 OI 失败时，`binanceAssetOiUsd` 仍当「已合计」展示，可能偏低却看起来确定。
- **建议**：记录 expected/got 合约数；不完整则合计为 unknown。
- **验收**：人为去掉某资产一只 OI 后合计带「不完整」且不可当确定 I1 替代。

### P2-5 市值映射路径正确区分可信度（已确认 · 低/正向）
- **位置**：`resolve_cap` L90–115；价格差 >20% 取消 trusted L261–267。
- **说明**：CG 明确 ID / 唯一代码 / Paprika 分列；非 COIN underlying 不映射。符合需求「待核对」语义。

## 3. 吸筹 / 箱体 / ATH：数据是否够，是否把候选当入场

### P3-1 T5/T6/T7 不可算（已确认 · 高）
- **证据**：`data-capability-audit.md`：日线/箱体/ATH/完整 OHLCV 覆盖为 0；`strategy-test-report.md` 覆盖表 `fullOhlcv: 0`。
- **影响**：页面若展示这些模板而不锁死「缺数据」，会被当成可交易策略。
- **建议**：模板状态机强制 `blocked_missing_data`；禁止进入篮子启用。
- **验收**：启用 T5 预检失败，列出缺日线字段。

### P3-2 T4 仅有横截面⑥线索（已确认 · 中）
- **证据**：⑥仅 3 合约；报告明确「不等于吸筹」。`cex_reserves.py` L61–64 写明储备下降 ≠ 买入。
- **建议**：T4 名称保留「疑似」，触发条件必须另要连续独立窗口 + 突破结构。

### P3-3 采集层未自动开多（已确认 · 正向）
- **位置**：`scanner.py` L199 `tradeStatus`：「观察，不自动生成开多指令」。
- **残留风险**：原型文案/跳转（P1-2）仍可能在产品层误导——属交互问题，非 scanner 发单。

## 4. 快照补核与历史回测的未来数据泄漏

### P4-1 补核时间晚于扫描结束（已确认 · 高 · 数据契约）
- **证据**：需求 §2：finishedAt≈20:07:37，GTC `capAsOf`≈20:09:54，`enrichedAt`≈20:11:58。
- **影响**：若回测/实验把补核市值当成 20:07 已可得 → **前视偏差**。
- **建议**：按字段存 `available_at`；实验绑定 revision；禁止把补核写回原快照时刻。
- **验收**：用「仅 finishedAt 前可得字段」重跑候选，GTC 相关结论变化可解释。

### P4-2 `scan.json` 原子写但无不可变历史 / 覆盖门槛（已确认 · 高）
- **位置**：`scanner.py` L280–281 `scan.tmp.json`→`replace`；无旧版归档、无最少覆盖率检查。
- **触发**：目录级部分失败仍 `received<<total` 时仍发布。
- **影响**：空/瘦快照覆盖成功件；无法审计「当时」规则。
- **建议**：C04 方案——门槛、部分成功、失败保留旧版、scan_id/revision。

### P4-3 `observations.jsonl` 重复追加（已确认 · 高 · 本次新确认）
- **位置**：`scanner.py` L244–252：`open(..., 'a')`；全文件无 `unlink`/`truncate`。
- **触发**：第二次 `--scan`。
- **影响**：同合约多行；「每合约一条」假设被破坏；下游若按行数当覆盖会虚高。
- **建议**：开跑前旋转旧文件或按 `scan_id` 分文件；禁止无 ID 追加到同一全局 jsonl。
- **验收**：连续跑两次，唯一 symbol 数仍 = 合约数，或第二份进入新 revision 文件。

### P4-4 无历史回测引擎故「回测泄漏」多为设计风险（设计建议）
- 完整 K 线未归档（只存 EMA 派生），无法做真回测；需先有 R1 归档再谈防泄漏测试。
